========================================================================
== 1. Building a score: a hymn tune in code
========================================================================
A SCORE is an immutable value: metadata, a measure map shared by all parts,
the parts (each with staves and voices of events), a chord-symbol track and
the spanners. Pitches, meters, keys, tempi and chord symbols are music-theory
values. Durations and offsets are rationals in whole notes (1/4 is a quarter).

The demo builds NEW BRITAIN, the tune of "Amazing Grace" (American folk
melody, 1829; words by John Newton, 1779), on two staves: the melody with two
verses of lyrics, and a bass line. 3/4, G major, a one-beat pickup. Bars 1-15
are repeated, once per verse, with a first and a second ending. The tune is
data (*MELODY*, *BASS*, *CHORDS*, *MEASURE-MARKS*, *VERSES* in demo.lisp); the
constructors turn it into elements:

  (make-measure-info :time (parse-meter "3/4") :key (parse-key "G major") :pickup-p t :length 1/4
                     :tempo
                     (list
                      (make-tempo-mark :tempo (make-tempo :bpm 84 :beat-unit 1/4) :text
                                       "Moderato")))

  (make-note-event :pitch (parse-pitch "B4") :duration 1/8 :lyrics
                   (list (make-lyric :verse 1 :text "ing" :syllabic :end :extender t)
                         (make-lyric :verse 2 :text "that" :extender t)))

  (make-chord-symbol-anchor :position '(2 . 1/2) :symbol (parse-chord-symbol "G7/B"))


Ties and slurs refer to notes by id. So the score is built in two steps. Step 1
(BUILD-HYMN) calls MAKE-SCORE with everything else and no ids at all: MAKE-SCORE
mints one for every element. Step 2 (ADD-TIES-AND-SLURS) reads the minted ids
of the notes and adds the tie (by rebuilding its start note, same id) and five
slurs over the melismas, through COPY-SCORE.

  (score-metadata *hymn*)
    => (:title "Amazing Grace" :subtitle "NEW BRITAIN" :composer "American folk melody, 1829" :lyricist "John Newton, 1779")
  (fset:size (score-measure-map *hymn*)) => 18
  (mapcar #'part-name (fset:convert 'list (score-parts *hymn*))) => ("Hymn tune")
  (mapcar #'staff-clef (part-staves (fset:first (score-parts *hymn*))))
    => (:treble :bass)
  (mapcar #'voice-name (part-voices (fset:first (score-parts *hymn*))))
    => ("Melody" "Bass")
  (fset:size (score-chord-symbols *hymn*)) => 18
  (fset:size (score-spanners *hymn*)) => 5
  (length (score-elements *draft*)) => 169   ; elements after step 1
  (length (score-elements *hymn*)) => 175   ; + 1 tie, 5 slurs

hyphen continues the word, _ is an extender line. A chord @1/2 is anchored

========================================================================
== 2. Element ids
========================================================================
Every element has an id: a string, unique in the score. MAKE-SCORE mints the
missing ones as PREFIX-SERIAL, the serial in base 36 (lower case), counting up
in document order. The prefix names the kind of element: m measure, tm tempo
mark, rh rehearsal mark, en ending, p part, st staff, v voice, e event (note,
rest or chord), n chord note, ti tie, ly lyric, dy dynamic, fe fermata, br
breath mark, h chord symbol, sp spanner. Ids are opaque: code asks
FIND-ELEMENT, it never parses one. Document order is a pre-order walk: the
measures (each followed by its marks), the part, its staves and voices, each
event followed by its marks and lyrics, then chord symbols and spanners.

The counter and the serials. Step 1 numbered its 169 elements 1 to 169 in
document order. COPY-SCORE in step 2 passed the counter on, so the tie and the
slurs got 170 to 175, although the tie sits inside a note of bar 7:

  (score-id-counter *draft*) => 169
  (score-id-counter *hymn*) => 175
  (equal (mapcar #'id-serial step-1)
         (loop for i from 1 to 169
               collect i))
    => t   ; serials 1, 2, ... 169
  (element-id tie) => "ti-4q"
  (id-serial (element-id tie)) => 170
  (tie-end tie) => "e-20"
  (element-parent *hymn* (element-id tie)) => #<note-event "e-1x">
  (mapcar #'element-id (fset:convert 'list (score-spanners *hymn*)))
    => ("sp-4r" "sp-4s" "sp-4t" "sp-4u" "sp-4v")
  (= (length ids) (length (remove-duplicates ids :test #'string=)))
    => t   ; all unique
  (every #'valid-id-p ids) => t
  (every #'ncname-p ids) => t   ; so MusicXML and MEI can carry them as xml ids
  (list (valid-id-p "P1") (valid-id-p "tenor-1") (valid-id-p "1e")
        (valid-id-p "m-3.p-4") (valid-id-p "e a"))
    => (t t nil nil nil)
  (make-note-event :id "1st" :pitch (parse-pitch "G4") :duration 1/4)
    -> simple-type-error: The value of score-protocol::id is "1st", which is not NIL or an id string.

Minting is deterministic: the same input gets the same ids, with no clock,
randomness or global state.

  (equal ids (mapcar #'element-id (score-elements (make-hymn)))) => t
  (score-equal *hymn* (make-hymn)) => t

Stable through COPY-SCORE. A copy with new metadata keeps every id and the
counter, and shares every element with the original (EQ):

  (getf (score-metadata copy) :arranger) => "demo"
  (equal ids (mapcar #'element-id (score-elements copy))) => t
  (every #'eq elements (score-elements copy)) => t
  (score-id-counter copy) => 175

Untouched subtrees stay EQ after a rebuild. Step 2 rebuilt the note that starts
the tie, and with it the path above it: the melody voice and the part. Of the
169 elements of step 1, the other 166 are the same objects in the hymn. The
three rebuilt ones kept their ids:

  (- 169 (length rebuilt)) => 166   ; EQ in both scores
  (mapcar #'element-id rebuilt) => ("p-o" "v-r" "e-1x")
  (mapcar (lambda (element) (class-name (class-of element))) rebuilt)
    => (part voice note-event)
  (eq (bar-measure *draft* 7) (bar-measure *hymn* 7)) => t
  (eq (voice-at *draft* 1) (voice-at *hymn* 1)) => t   ; the bass voice
  (eq (melody-at *draft* 7 0) (melody-at *hymn* 7 0)) => nil   ; the tied note
  (equal (event-lyrics (melody-at *draft* 7 0)) (event-lyrics (melody-at *hymn* 7 0)))
    => t   ; its lyrics: the same objects

A deleted element's id is never reused. Removing the Em of bar 12 and then
adding a C there gives the C a new serial, one past the counter, not the
Em's id:

  (element-id em) => "h-4k"
  (find-element fewer (element-id em) :errorp nil) => nil
  (score-id-counter fewer) => 175   ; deleting mints nothing
  (element-id c) => "h-4w"
  (id-serial (element-id c)) => 176
  (find-element more (element-id em) :errorp nil) => nil

Lookups. FIND-ELEMENT and ELEMENT-PARENT go from an id to its element and up
the tree. An unknown id signals UNKNOWN-ELEMENT, with a USE-VALUE restart:

  (lyric-text (find-element *hymn* (element-id lyric))) => "ing"
  (loop for id = (element-id lyric) then (element-id parent)
        for parent = (element-parent *hymn* id)
        while parent
        collect (element-id parent))
    => ("e-y" "v-r" "p-o")   ; lyric -> note -> voice -> part
  (find-element *hymn* "e-zzz" :errorp nil) => nil
  (find-element *hymn* "e-zzz")
    -> unknown-element: no element with id "e-zzz"
  (handler-bind ((unknown-element (lambda (c) (use-value :missing c))))
    (find-element *hymn* "e-zzz"))
    => :missing

Slice ids. A measure spans every part, so one voice's share of a measure (a
part's <measure> in MusicXML) is named by joining two ids with a dot. A slice
id is an NCName that no element can have, since element ids have no dot:

  (slice-id (element-id measure) (element-id bass))
    => "m-c.v-3h"   ; bar 9 of the bass
  (list (ncname-p slice) (valid-id-p slice)) => (t nil)
  (find-slice *hymn* "m-c.v-3h") => (values #<measure-info "m-c"> #<voice "v-3h">)
  (find-slice *hymn* "m-c.e-26" :errorp nil) => nil   ; e-26 is an event: no slice
  (element-id (melody-at *hymn* 9 0)) => "e-26"
  (slice-id "m-1" "not an id")
    -> simple-type-error: The value of element-id is "not an id", which is not an id string.

========================================================================
== 3. Bars and positions
========================================================================
Bar numbers are indices into the measure map. When the first measure is a
pickup it is bar 0, so the first full bar is bar 1. Time and key signatures are
inherited from the latest measure that has one. BAR-LENGTH is the meter's bar,
or the measure's own LENGTH (the pickup's quarter). BAR-START adds them up:

  (score-first-bar *hymn*) => 0
  (score-last-bar *hymn*) => 17
  (score-duration *hymn*) => 13   ; 1/4 + 17 bars of 3/4

  bar  id     time  key      length  start  marks
    0  m-1    3/4   G major  1/4     0      pickup Moderato q=84
    1  m-3    3/4   G major  3/4     1/4    |: rehearsal A
    2  m-5    3/4   G major  3/4     1
    3  m-6    3/4   G major  3/4     7/4
    4  m-7    3/4   G major  3/4     5/2
    5  m-8    3/4   G major  3/4     13/4
    6  m-9    3/4   G major  3/4     4
    7  m-a    3/4   G major  3/4     19/4
    8  m-b    3/4   G major  3/4     11/2
    9  m-c    3/4   G major  3/4     25/4   rehearsal B
   10  m-e    3/4   G major  3/4     7
   11  m-f    3/4   G major  3/4     31/4
   12  m-g    3/4   G major  3/4     17/2
   13  m-h    3/4   G major  3/4     37/4
   14  m-i    3/4   G major  3/4     10
   15  m-j    3/4   G major  3/4     43/4
   16  m-k    3/4   G major  3/4     23/2   [1. :| x2
   17  m-m    3/4   G major  3/4     49/4   [2. final barline
  (measure-info-time (bar-measure *hymn* 5)) => nil   ; inherited: nothing stored

A position is (BAR . OFFSET), the offset a rational in whole notes from the
start of the bar. ABSOLUTE-OFFSET turns it into whole notes from the start of
the score, OFFSET-POSITION goes back. The end of a bar is the same instant as
the start of the next, and OFFSET-POSITION gives the next bar. In a score with
a pickup, (1 . 0) is the pickup's length:

  (absolute-offset *hymn* '(0 . 0)) => 0
  (absolute-offset *hymn* '(1 . 0)) => 1/4   ; the pickup's length
  (absolute-offset *hymn* '(1 . 5/8)) => 7/8   ; the G eighth of "-ing"
  (absolute-offset *hymn* '(9 . 5/8)) => 55/8
  (absolute-offset *hymn* '(1 . 3/4)) => 1   ; the end of bar 1 ...
  (absolute-offset *hymn* '(2 . 0)) => 1   ; ... is the start of bar 2
  (offset-position *hymn* 1) => (2 . 0)
  (offset-position *hymn* 1/8) => (0 . 1/8)
  (offset-position *hymn* 55/8) => (9 . 5/8)
  (offset-position *hymn* 13) => (17 . 3/4)   ; the very end

ELEMENT-POSITION places any element: an event by its voice measure and the
durations before it, a mark or lyric at its event, a tie at its start note, a
slur at its first event, a measure mark at its bar. Parts, staves and voices
have no position:

  element  what                                   position
  e-y      B4 eighth, "-ing"                      (1 . 1/2)
  ly-10    its verse-2 lyric "that"               (1 . 1/2)
  br-21    breath mark on the held D5             (8 . 0)
  e-22     B4 quarter, "I"                        (8 . 1/2)
  ti-4q    the tie D5 ~ D5                        (7 . 0)
  sp-4u    the slur over "found"                  (12 . 0)
  tm-2     tempo mark Moderato                    (0 . 0)
  rh-d     rehearsal mark B                       (9 . 0)
  en-n     second ending                          (17 . 0)
  h-4f     chord symbol D7/F#                     (8 . 0)
  e-43     bass rest, first ending                (16 . 1/2)
  v-3h     the bass voice                         nil

Round trips. OFFSET-POSITION of ABSOLUTE-OFFSET gives back the position of every
event (59 of them, both voices), and the other way round every offset on the
1/24 grid from 0 to 13 comes back (313 offsets, triplet eighths included):

  (length events) => 59
  (every
   (lambda (event)
     (let ((position (element-position *hymn* (element-id event))))
       (equal (offset-position *hymn* (absolute-offset *hymn* position)) position)))
   events)
    => t
  (loop for k from 0 to (* 13 24)
        always (= (absolute-offset *hymn* (offset-position *hymn* (/ k 24)))
                  (/ k 24)))
    => t
  (loop for bar from 0 to 17
        always (equal (offset-position *hymn* (bar-start *hymn* bar)) (cons bar 0)))
    => t   ; every bar-start is (bar . 0)

INVALID-POSITION. A bar outside 0..17, an offset past its bar (the pickup is
only a quarter long), or an absolute offset outside 0..13 signals
INVALID-POSITION with the argument, inside a USE-VALUE restart. A position
that isn't a cons, or a float offset, is a TYPE-ERROR:

  (absolute-offset *hymn* '(0 . 1/2))
    -> invalid-position: invalid position (0 . 1/2): outside the score
  (absolute-offset *hymn* '(18 . 0))
    -> invalid-position: invalid position (18 . 0): outside the score
  (offset-position *hymn* 14)
    -> invalid-position: invalid position 14: outside the score
  (offset-position *hymn* -1/8)
    -> invalid-position: invalid position -1/8: outside the score
  (bar-length *hymn* 18)
    -> invalid-position: invalid position 18: no such bar
  (bar-start *hymn* -1)
    -> invalid-position: invalid position -1: no such bar
  (absolute-offset *hymn* 3)
    -> simple-type-error: The value of position is 3, which is not a (bar . offset) position.
  (offset-position *hymn* 0.5)
    -> simple-type-error: The value of score-protocol::offset is 0.5, which is not of type rational.
  (handler-case (absolute-offset *hymn* '(18 . 0))
                (invalid-position (c) (invalid-position-position c)))
    => (18 . 0)

A handler can answer with USE-VALUE. Here a past-the-end offset is clamped to
the last position, and a bar past the end to the score's duration:

  (handler-bind ((invalid-position
                  (lambda (c) (use-value (cons 17 (bar-length *hymn* 17)) c))))
    (offset-position *hymn* 20))
    => (17 . 3/4)
  (handler-bind ((invalid-position
                  (lambda (c) (use-value (score-duration *hymn*) c))))
    (list (absolute-offset *hymn* '(4 . 1/4)) (absolute-offset *hymn* '(25 . 0))))
    => (11/4 13)
  (let ((empty (make-score)))
    (list (score-first-bar empty) (score-last-bar empty) (score-duration empty)
          (handler-case (absolute-offset empty '(1 . 0))
                        (invalid-position nil :invalid))))
    => (1 0 0 :invalid)   ; no measures: every position is invalid

========================================================================
== 4. Validation: CHECK-SCORE and VALIDATE-SCORE
========================================================================
MAKE-SCORE accepts any score whose values have the right types. Whether they
fit together is reported, not refused: CHECK-SCORE returns a list of
SCORE-ISSUEs (kind, subject id, bar, detail) and never signals. The hymn has
none. Here is a copy with four mistakes, each made with REBUILD-EVENT or
REBUILD-MEASURE (demo.lisp: rebuild one element through COPY-SCORE, keep its
id). The edit operations of section 7 can't make them: an edit that adds an
issue is refused with EDIT-BREAKS-SCORE.

  (check-score *hymn*) => nil

1. An overfull bar: the E4 quarter of bar 3 becomes a half note.

  (setf *broken* (rebuild-event *broken* (copy-note (melody-at *broken* 3 1) :duration 1/2)))

2. A tie to a different pitch: the D5 that the bar-7 tie ends on becomes C5.

  (setf *broken*
          (rebuild-event *broken* (copy-note (melody-at *broken* 8 0) :pitch (parse-pitch "C5"))))

3. A lyric on a rest: the bass rest of the pickup gets a syllable.

  (setf *broken*
          (rebuild-event *broken*
                         (make-rest-event :id (element-id (bass-at *broken* 0 0)) :duration 1/4
                                          :lyrics (list (make-lyric :text "Oh")))))

4. An ending past the end: the second ending, on the last bar, claims three
measures.

  (setf *broken*
          (let ((last (bar-measure *broken* 17)))
            (rebuild-measure *broken*
                             (copy-measure last :ending
                                           (make-ending :id
                                                        (element-id (measure-info-ending last))
                                                        :passes '(2) :measures 3)))))

  (length issues) => 4
  (sort (mapcar #'score-issue-kind issues) #'string<)
    => (:bad-ending :measure-duration :misplaced-lyric :tie-pitch)

  kind               id     bar  the id names                     detail
  :bad-ending        en-n    17  ending 2. over 3 measures        nil
  :measure-duration  v-r      3  voice "Melody"                   (:expected 3/4 :actual 1)
  :misplaced-lyric   ly-4w    0  lyric "Oh" on rest-event e-3i    nil
  :tie-pitch         ti-4q    7  tie e-1x D5 ~ e-20 C5            nil

  (score-issue-detail (funcall by-kind :measure-duration))
    => (:expected 3/4 :actual 1)
  (score-issue-bar (funcall by-kind :measure-duration)) => 3
  (score-issue-id (funcall by-kind :measure-duration)) => "v-r"
  (score-issue-id (funcall by-kind :tie-pitch)) => "ti-4q"
  (score-issue-bar (funcall by-kind :bad-ending)) => 17

CHECK-SCORE never signals, so even the broken score goes through it with no
handler firing. It works from its own bar table, not ABSOLUTE-OFFSET:

  (let ((signals 0))
    (handler-bind ((condition (lambda (c) (declare (ignore c)) (incf signals))))
      (check-score *broken*))
    signals)
    => 0

VALIDATE-SCORE is the strict entry point: it returns a valid score as it is,
and otherwise signals SCORE-INVARIANT-VIOLATION with the issues, inside a
CONTINUE restart that returns the score as it is:

  (eq (validate-score *hymn*) *hymn*) => t
  (validate-score *broken*)
    -> score-invariant-violation: score invariant violated: 4 issues, first #S(score-issue :kind :misplaced-lyric :id "ly-4w" :bar 0 :detail nil)
  (handler-case (validate-score *broken*)
                (score-invariant-violation (c)
                 (length (score-invariant-violation-issues c))))
    => 4
  (eq
   (handler-bind ((score-invariant-violation
                   (lambda (c)
                     (setf seen
                             (mapcar #'score-issue-kind
                                     (score-invariant-violation-issues c)))
                     (continue c))))
     (validate-score *broken*))
   *broken*)
    => t   ; resumed with CONTINUE
  (sort seen #'string<)
    => (:bad-ending :measure-duration :misplaced-lyric :tie-pitch)
  (typep (make-condition 'score-invariant-violation) 'score-error) => t

========================================================================
== 5. Provenance and confidence
========================================================================
Every element can say where it came from and how sure its producer was.
PROVENANCE is a struct: SOURCE (:user, :musicxml, :midi, :omr, :transcription
...), BACKEND, PAGE, BBOX, TIME-RANGE. CONFIDENCE is NIL (not recorded:
certain) or a real in 0..1. A recognizer marks its guesses, and a review step
asks UNCERTAIN-ELEMENTS for the ones below a threshold (default 0.8).

Here the same builder plays a recognition step reading the tune from page 1:
every note, lyric and chord symbol gets provenance :OMR, and seven elements a
confidence and a bounding box (*RECOGNITION* in demo.lisp):

  (equal (mapcar #'element-id (score-elements read))
         (mapcar #'element-id (score-elements *hymn*)))
    => t   ; the same ids: same input, same order
  (score-equal read *hymn*) => nil   ; provenance and confidence count
  (provenance-source (element-provenance (melody-at read 1 0))) => :omr
  (element-confidence (melody-at read 1 0)) => nil   ; certain
  (element-provenance (melody-at *hymn* 1 0)) => nil   ; built by hand: none

(uncertain-elements read), in document order:

========================================================================
== 6. The canonical s-expression form
========================================================================
SCORE-TO-SEXP writes the reference serialization: a form of conses, keywords,
strings and numbers, with every id and the id counter. Keys come in a fixed
order and defaults are left out, so equal scores give EQUAL forms. Pitches,
meters and keys are written as music-theory text ("F#2", "3/4", "G major").
The hymn's form starts like this:

  (:score :metadata
   (:title "Amazing Grace" :subtitle "NEW BRITAIN" :composer "American folk melody, 1829"
    :lyricist "John Newton, 1779")
   :id-counter 175 :measures
   ((:measure :id "m-1" :time "3/4" :key "G major" :pickup t :length 1/4 :tempo
     ((:tempo-mark :id "tm-2" :bpm 84 :beat-unit 1/4 :text "Moderato")))
    (:measure :id "m-3" :repeat-start t :rehearsal (:rehearsal :id "rh-4" :text "A"))
    (:measure :id "m-5") (:measure :id "m-6") (:measure :id "m-7") (:measure :id "m-8")
    (:measure :id "m-9") (:measure :id "m-a") (:measure :id "m-b")
    (:measure :id "m-c" :rehearsal (:rehearsal :id "rh-d" :text "B")) (:measure :id "m-e")
    (:measure :id "m-f") (:measure :id "m-g") (:measure :id "m-h") (:measure :id "m-i")
    (:measure :id "m-j")
    (:measure :id "m-k" :repeat-end 2 :ending (:ending :id "en-l" :passes (1)))
    (:measure :id "m-m" :barline :final :ending (:ending :id "en-n" :passes (2))))
   :parts
   ((:part :id "p-o" :name "Hymn tune" :staves
     ((:staff :id "st-p") (:staff :id "st-q" :clef :bass)) :voices
     ((:voice :id "v-r" :name "Melody" :measures
       (((:note :id "e-s" :pitch "D4" :duration 1/4 :dynamic (:dynamic :id "dy-t" :value :mp)
          :lyrics ((:lyric :id "ly-u" :text "A" :syllabic :begin))))
        ((:note :id "e-v" :pitch "G4" :duration 1/2 :lyrics
          ((:lyric :id "ly-w" :text "maz" :syllabic :middle)
           (:lyric :id "ly-x" :verse 2 :text "grace")))
         (:note :id "e-y" :pitch "B4" :duration 1/8 :lyrics
  ... 138 more lines

  14494 characters when printed with PRIN1 under WITH-STANDARD-IO-SYNTAX.
  (first form) => :score
  (getf (rest form) :id-counter) => 175

ELEMENT-TO-SEXP writes one element and everything inside it: the B4 eighth of
bar 1 with its two lyrics, and the chord symbol in bar 8:

  (:note :id "e-y" :pitch "B4" :duration 1/8 :lyrics
   ((:lyric :id "ly-z" :text "ing" :syllabic :end :extender t)
    (:lyric :id "ly-10" :verse 2 :text "that" :extender t)))
  (:chord-symbol :id "h-4f" :bar 8 :offset 0 :symbol
   (:root "D" :quality :dominant-7 :bass "F#" :text "D7/F#" :dialect :pop))
  (element-id (sexp-to-element (element-to-sexp (melody-at *hymn* 1 1)))) => "e-y"

Reading it back. The text goes through READ with *READ-EVAL* NIL, then
SEXP-TO-SCORE. The copy is SCORE-EQUAL (model equality: content, ids,
provenance and confidence), has the same counter, writes the same form, and
mints the same next id:

  (equal read-form form) => t
  (score-equal copy *hymn*) => t
  (eq copy *hymn*) => nil
  (score-id-counter copy) => 175
  (equal (score-to-sexp copy) form) => t
  (check-score copy) => nil
  (list (next-id *hymn*) (next-id copy)) => ("h-4w" "h-4w")

SCORE-EQUAL ignores the counter, which is bookkeeping, and counts everything
else:

  (score-equal *hymn*
               (sexp-to-score
                (list* :score :id-counter 999
                       (let ((plist (copy-list (rest form))))
                         (remf plist :id-counter)
                         plist))))
    => t   ; the same score with counter 999
  (score-equal *hymn* *draft*) => nil   ; no tie, no slurs
  (score-equal *hymn* *broken*) => nil
  (score-equal *broken* (sexp-to-score (score-to-sexp *broken*)))
    => t   ; invalid scores round-trip too

Reader errors. A form that isn't a kind keyword and a proper plist, a kind the
key doesn't take, an unknown key or a key given twice signals
SCORE-FORMAT-ERROR (FORMAT :SEXP). Its POSITION is the offending sub-form:

  (:score :measures ((:measure :time "3/4" :key "G major" :pickup t :lenght 1/4))
   :parts nil)
    -> score-format-error: sexp format error: unknown key :LENGHT at (:measure :time "3/4" :key "G major" :pickup t :lenght 1/4)
       position: (:measure :time "3/4" :key "G major" :pickup t :lenght 1/4)
  (:score :measures ((:measure :time "3/4")) :parts
   ((:part :staves ((:staff)) :voices
     ((:voice :measures
       (((:note :pitch "G4" :duration 3/4 :fermata (:tie :end "e-9")))))))))
    -> score-format-error: sexp format error: expected a form of kind :FERMATA at (:tie :end "e-9")
       position: (:tie :end "e-9")
  (:score :measures ((:measure :time "3/4")) :parts
   ((:part :staves ((:staff)) :voices
     ((:voice :measures
       (((:note :pitch "G4" :duration 3/4 :lyrics ((:lyric :text "la" :verse))))))))))
    -> score-format-error: sexp format error: not a property list at (:lyric :text "la" :verse)
       position: (:lyric :text "la" :verse)
  (:score :measures ((:measure :time "3/4" :time "6/8")) :parts nil)
    -> score-format-error: sexp format error: key :TIME given twice at (:measure :time "3/4" :time "6/8")
       position: (:measure :time "3/4" :time "6/8")
  (:scor :measures nil :parts nil)
    -> score-format-error: sexp format error: expected a :score form at (:scor :measures nil :parts nil)
       position: (:scor :measures nil :parts nil)

Errors from the constructors and from music-theory's parsers are not wrapped:
they reach the caller with their own restarts. A pitch that doesn't parse can
be replaced with USE-VALUE, a duration that is out of range with STORE-VALUE,
and the reading goes on:

  (sexp-to-score bad-pitch)
    -> invalid-pitch: invalid-pitch "H4": unknown letter
  (let ((score
         (handler-bind ((music-theory:invalid-pitch
                         (lambda (c) (use-value (parse-pitch "B4") c))))
           (sexp-to-score bad-pitch))))
    (pitch-name (note-pitch (event-at score 0 1 0))))
    => "B4"
  (sexp-to-score bad-duration)
    -> simple-type-error: The value of score-protocol::duration is -3/4, which is not of type (rational (0)).
  (let ((score
         (handler-bind ((type-error (lambda (c) (store-value 3/4 c))))
           (sexp-to-score bad-duration))))
    (list (event-duration (event-at score 0 1 0)) (check-score score)))
    => (3/4 nil)

========================================================================
== 7. Editing: operations as values
========================================================================
SC1 makes every change to a score a value. An EDIT-OPERATION names one change
and APPLY-EDIT returns (values new-score change-set). The score passed in never
changes. The new one shares every untouched element with it. Operations name
their targets by id, never by place, so a logged operation means the same
thing after other edits. The change set lists the ids the edit CREATED,
REMOVED and MODIFIED. An element is modified when its own slots change or its
children's ids do. So when a note changes pitch, its voice is not modified.
When a lyric's text changes, the note it sits on is not modified either.

Seven edits on the hymn, each applied to the result of the one before. Each
prints the operation's constructor call and its canonical form, the bars it
touches, the change set, and how much of the old score the new one shares:

1. SET-PITCH. Bar 15's A4 becomes F#4, a leading note into the last bar. The
note keeps its id and its lyrics, and only the note is modified. The voice
and the part above it are rebuilt to hold the new note. Every other element
of the score is the old score's own object:

  (make-set-pitch :id (melody-id score 15 1) :pitch (parse-pitch "F#4"))
    => (:set-pitch :id "e-37" :pitch "F#4")

  bar 15  before  B4:h A4:q
          after   B4:h F#4:q

  created   -
  removed   -
  modified  e-37 (F#4:q in bar 15)
  EQ        172 of the 175 elements kept are the old objects
  rebuilt   p-o, v-r, e-37
  counter   175 -> 175

  (eq (voice-at score 1) (voice-at *hymn* 1)) => t   ; the bass voice
  (every #'eq (fset:convert 'list (score-measure-map score))
         (fset:convert 'list (score-measure-map *hymn*)))
    => t   ; every measure
  (eq (melody-at score 15 0) (melody-at *hymn* 15 0)) => t   ; the B4 beside it

2. SET-DURATION across a barline. Bar 12's E4, the end of a melisma, becomes a
half note. It starts on the third beat, so it runs over the barline. The first
piece is the note itself, with its id and its marks. The piece in bar 13 is a
new note, and a new tie joins the two. The longer note covers the first beat
of bar 13, so the D4 that started there is removed, and the rest of its time
becomes a quarter rest. The slur that ended on that D4 has lost an endpoint,
and the cascade removes it. The new ids continue the series. The counter was
175, and the tie, the piece and the rest get serials 176, 177 and 178, in
document order:

  (make-set-duration :id (melody-id score 12 1) :duration 1/2)
    => (:set-duration :id "e-2s" :duration 1/2)

  bar 12  before  G4:h( E4:q
          after   G4:h E4:q~
  bar 13  before  D4:h) D4:q
          after   E4:q r:q D4:q

  created   ti-4w (tie to e-4x), e-4x (E4:q in bar 13), e-4y (r:q in bar 13)
  removed   e-2t (D4:h in bar 13), sp-4u (slur e-2p to e-2t)
  modified  v-r (voice Melody), e-2s (E4:q~ in bar 12)
  EQ        170 of the 173 elements kept are the old objects
  rebuilt   p-o, v-r, e-2s
  counter   175 -> 178

  (mapcar #'id-serial (change-set-created (last-changes))) => (176 177 178)
  (tie-end (note-tie (melody-at score 12 1))) => "e-4x"

3. A shorter SET-DURATION. The final G4 of the second ending goes from a dotted
half to a half. The time it gave up is a gap, and the gap is filled with a
quarter rest. Its fermata and its lyric stay on the note:

  (make-set-duration :id (melody-id score 17 0) :duration 1/2)
    => (:set-duration :id "e-3e" :duration 1/2)

  bar 17  before  G4:h.^
          after   G4:h^ r:q

  created   e-4z (r:q in bar 17)
  removed   -
  modified  v-r (voice Melody), e-3e (G4:h^ in bar 17)
  EQ        173 of the 176 elements kept are the old objects
  rebuilt   p-o, v-r, e-3e
  counter   178 -> 179

4. INSERT-EVENT into a full bar. Bar 16, the first ending, holds G4 h and D4 q.
An E4 eighth goes in before the D4. Everything after it in the bar moves an
eighth later. That would make the bar an eighth too long, and there is no
trailing rest to absorb it. So APPLY-EDIT signals MEASURE-OVERFULL, with the
voice, the bar and the excess:

  (apply-edit score op)
    -> measure-overfull: invalid edit #<insert-event>: voice "v-r" overfills bar 16 by 1/8
  (handler-case (apply-edit score op)
                (measure-overfull (c)
                 (list (measure-overfull-voice c) (measure-overfull-bar c)
                       (measure-overfull-excess c))))
    => ("v-r" 16 1/8)
  (restarts-around (lambda () (apply-edit score op)) 'measure-overfull)
    => (reflow skip-edit use-value)

The REFLOW restart applies the same operation with REFLOW true. The E4 takes
its eighth, and the rest of the voice moves an eighth later and re-flows into
the bars. The D4 now crosses the barline, so it becomes two tied eighths. The
G4 of bar 17 moves, keeping its id. The quarter rest from step 3 is cut at
the end of the score, and what is left becomes a new eighth rest. REFLOW
follows the voice's time line bar after bar, so it pushes music from the first
ending into the second. Without the rest at the end, a note would be pushed
past the end of the score, which is EDIT-POSITION-INVALID.

  (score-equal reflowed
               (apply-edit score
                           (make-insert-event :voice (edit-voice op) :measure
                                              (edit-measure op) :offset 1/2 :event
                                              (edit-event op) :reflow t)))
    => t   ; the restart = the operation with :reflow t

  (make-insert-event :voice (voice-id score 0) :measure (measure-id score 16) :offset
                     1/2 :event
                     (make-note-event :pitch (parse-pitch "E4") :duration 1/8)
                     :reflow t)

names the operation. Some failures have their own subtype. Every refusal is
signalled before anything changes, inside the restarts SKIP-EDIT and USE-VALUE:

  (apply-edit *hymn* (make-set-pitch :id "e-zz" :pitch (parse-pitch "C5")))
    -> edit-target-missing: invalid edit #<set-pitch>: no element with id "e-zz"

              (make-set-pitch :id (voice-id *hymn* 0) :pitch (parse-pitch "C5")))

  (typep (make-condition 'edit-target-missing) 'unknown-element) => t

SKIP-EDIT returns the score as it was, with an empty change set. USE-VALUE
applies another operation instead:

  (multiple-value-bind (score changes)
      (handler-bind ((invalid-edit #'skip-edit))
        (apply-edit *hymn* (make-set-pitch :id "e-zz" :pitch (parse-pitch "C5"))))
    (list (eq score *hymn*) (change-set-empty-p changes)))
    => (t t)
  (multiple-value-bind (score changes)
      (handler-bind ((edit-target-missing
                      (lambda (c)
                        (use-value
                         (make-set-pitch :id (melody-id *hymn* 15 1) :pitch
                                         (parse-pitch "F#4"))
                         c))))
        (apply-edit *hymn* (make-set-pitch :id "e-zz" :pitch (parse-pitch "F#4"))))
    (list (bar-text score 0 15) (change-set-modified changes)))
    => ("B4:h F#4:q" ("e-37"))

========================================================================
== 8. Undo, composition and the canonical form of operations
========================================================================
INVERT-EDIT score op returns an operation that undoes OP on SCORE. It is read
off the pair (before, after), so it undoes what was actually applied, whatever
restart or cascade led there, and it restores removed elements with their own
ids. It is built from the library's own classes, mostly restore-style
operations in a COMPOSITE-EDIT, so it serialises like any other operation.

The inverse of each step of section 7, taken on the score the step was applied
to:

  step  operation       inverse: ops  form size  kinds
     1  set-pitch                  1        559  set-voice-measures
     2  set-duration              61      16946  remove-chord-symbol remove-spanner
                                               set-voice-measures replace-measure
                                               add-chord-symbol add-spanner
     3  set-duration               1        351  set-voice-measures
     4  insert-event               1        798  set-voice-measures
     5  add-spanner                1         69  remove-spanner
     6  add-mark                   1        676  set-voice-measures
     7  add-mark                   1        565  set-voice-measures

Most inverses are a single restore. Step 1's restores bar 15 of the melody as it
was, with the note's own id, lyrics and provenance:

  (:composite :ops
   ((:set-voice-measures :voice "v-r" :measure "m-j" :measures
     (((:note :id "e-34" :pitch "B4" :duration 1/2 :lyrics
        ((:lyric :id "ly-35" :text "now")
         (:lyric :id "ly-36" :verse 2 :text "first")))
       (:note :id "e-37" :pitch "A4" :duration 1/4 :lyrics
        ((:lyric :id "ly-38" :text "I")
         (:lyric :id "ly-39" :verse 2 :text "be" :syllabic :begin))))))))

Step 2's inverse holds 61 operations. It removes every chord symbol, silences
both voices, strips the measures and puts all of it back. The step removed a
slur from the middle of SCORE-SPANNERS, and the direct restore (remove the
spanners after it, add them back) was judged to collide with itself. It
doesn't, since the removals run first. The result is still exact, as the next
lines show, but the inverse is the size of the score: score-protocol#7.

Undo: the inverses applied in reverse order, newest first. Each one gives a
score SCORE-EQUAL to the score before its step. Its change set mirrors the
step's: CREATED is the step's REMOVED, REMOVED its CREATED, and MODIFIED holds
the same ids:

  undo step 7: score-equal to the score before it: t; change set mirrored: t
  undo step 6: score-equal to the score before it: t; change set mirrored: t
  undo step 5: score-equal to the score before it: t; change set mirrored: t
  undo step 4: score-equal to the score before it: t; change set mirrored: t
  undo step 3: score-equal to the score before it: t; change set mirrored: t
  undo step 2: score-equal to the score before it: t; change set mirrored: t
  undo step 1: score-equal to the score before it: t; change set mirrored: t

  (score-equal score *hymn*) => t   ; back to the hymn of section 1
  (eq score *hymn*) => nil   ; an equal value, not the same object
  (score-id-counter score) => 185   ; serials are never reused

COMPOSE-EDITS makes one operation of several. Its members are applied in
order, each to the score the one before produced. The cascade and the check
run once, at the end. The seven steps as one operation:

  (:composite :ops
   ((:set-pitch :id "e-37" :pitch "F#4") (:set-duration :id "e-2s" :duration 1/2)
    (:set-duration :id "e-3e" :duration 1/2)
    (:insert-event :voice "v-r" :measure "m-k" :offset 1/2 :event
     (:note :pitch "E4" :duration 1/8) :reflow t)
    (:add-spanner :spanner (:spanner :kind :slur :start "e-50" :end "e-3c"))
    (:add-mark :target "e-3a" :mark (:fermata))
    (:add-mark :target "e-1r" :mark (:lyric :text "soul"))))

  (score-equal after *edited*) => t   ; the same score as step by step

  created   ti-4w (tie to e-4x), e-4x (E4:q in bar 13), e-4y (r:q in bar 13),
            fe-55 (fermata), e-50 (E4:e in bar 16), ti-51 (tie to e-52),
            e-52 (D4:e in bar 17), e-53 (r:e in bar 17), sp-54 (slur e-50 to e-3c)
  removed   e-2t (D4:h in bar 13), sp-4u (slur e-2p to e-2t)
  modified  v-r (voice Melody), ly-1s (lyric "soul"), e-2s (E4:q~ in bar 12),
            e-37 (F#4:q in bar 15), e-3a (G4:h^ in bar 16), e-3c (D4:e~ in bar 16),
            e-3e (G4:h^ in bar 17)

The composite's change set runs from the hymn to the result. The rest made in
step 3 and cut in step 4 doesn't appear in it. Its inverse is again one
operation, and it undoes all seven steps:

  (score-equal (apply-edit after (invert-edit *hymn* composite)) *hymn*) => t
  (eq (compose-edits (first ops)) (first ops)) => t   ; one operation is itself
  (length (edit-ops (compose-edits composite (first ops))))
    => 8   ; composites are spliced
  (multiple-value-bind (score changes)
      (apply-edit *hymn* (compose-edits))
    (list (score-equal score *hymn*) (change-set-empty-p changes)))
    => (t t)   ; the empty composite

EDIT-TO-SEXP writes an operation in the canonical form, the way sexp.lisp
writes elements: the kind keyword, then the slots as keys in a fixed order,
with the defaults left out. Given elements are element forms, and pitches,
meters, keys and intervals are music-theory text. The text is read back with
*READ-EVAL* NIL and SEXP-TO-EDIT. The copy writes the same form, and it
applies to the hymn exactly as the original does:

  (length text) => 637   ; characters
  (equal (edit-to-sexp copy) form) => t
  (eq copy composite) => nil
  (list (score-equal a b) (equalp ca cb))
    => (t t)   ; equal scores, equal change sets
  (every
   (lambda (inverse)
     (equal (edit-to-sexp (sexp-to-edit (edit-to-sexp inverse)))
            (edit-to-sexp inverse)))
   inverses)
    => t   ; the inverses round-trip too

A form with an unknown kind or key signals SCORE-FORMAT-ERROR (FORMAT :SEXP),
with the offending form as POSITION:

  (:set-pitch :id "e-37" :pitch "F#4" :colour :red)
    -> score-format-error: sexp format error: unknown key :COLOUR at (:set-pitch :id "e-37" :pitch "F#4" :colour :red)
       position: (:set-pitch :id "e-37" :pitch "F#4" :colour :red)
  (:set-pitches :id "e-37" :pitch "F#4")
    -> score-format-error: sexp format error: expected an operation form at (:set-pitches :id "e-37" :pitch "F#4")
       position: (:set-pitches :id "e-37" :pitch "F#4")
  (:composite :ops
   ((:set-pitch :id "e-37" :pitch "F#4")
    (:add-mark :target "e-3a" :mark (:fermata :shape))))
    -> score-format-error: sexp format error: not a property list at (:fermata :shape)
       position: (:fermata :shape)

========================================================================
== 9. Re-barring with SET-TIME
========================================================================
SET-TIME re-bars a region of the score. The region runs from the measure to the
next measure that has a time signature of its own. In the hymn only bar 0 has
one, so a SET-TIME on bar 1 would re-bar the whole tune. Giving bar 5 its own
3/4 first ends the region at bar 4. That changes only bar 5's measure:

  (change-set-modified changes) => ("m-8")
  (meter-string (measure-info-time (bar-measure bounded 5))) => "3/4"

3/4 to 6/8 on bars 1-4. A 6/8 bar holds six eighths, the same length as a 3/4
bar. Every barline stays where it was, so the measures are kept, nothing
moves and nothing is tied. Only bar 1's own TIME changes. Beaming and beat
grouping are left to the engraver:

  (list (change-set-created changes) (change-set-removed changes)
        (change-set-modified changes))
    => (nil nil ("m-3"))
  (loop for bar from 1 to 4
        always (and
                (eq (fset:lookup (voice-measures (voice-at six-eight 0)) bar)
                    (fset:lookup (voice-measures (voice-at bounded 0)) bar))
                (eq (fset:lookup (voice-measures (voice-at six-eight 1)) bar)
                    (fset:lookup (voice-measures (voice-at bounded 1)) bar))))
    => t   ; bars 1-4 of both voices are the same objects
  (mapcar (lambda (bar) (meter-string (bar-time six-eight bar))) '(1 2 3 4 5))
    => ("6/8" "6/8" "6/8" "6/8" "3/4")

3/4 to 2/4 on the same bars. The region lasts 3 whole notes, which makes six
bars of 2/4. Every voice keeps its time line, and the music re-flows into the
new bars. A measure is kept when a new bar starts where it started: bar 1
(offset 0) and old bar 3 (offset 3/2) keep their ids, and with them anything
on them. Old bars 2 and 4 started inside a new bar, so they are removed. The
other four bars are new measures. A note that now crosses a barline is split
into tied pieces, so ties flow across the new barlines. Chord symbols in the
region keep their absolute offsets: G7/B moves from (2 . 1/2) to (3 . 1/4).
Those after the region stay with their measures, two bars later. Before and
after:

    1  m-3    3/4   G4:h B4:e( G4:e)        G2:h.[mp]          G
    2  m-5    3/4   B4:h A4:q               G2:h B2:q          G7/B@1/2

A refusal. SET-TIME on bar 8 to 2/4 would re-bar bars 8-17. Bar 9 starts 3/4
after bar 8, inside a 2/4 bar, so it would be removed. But bar 9 carries
rehearsal mark B, and re-barring would lose it. Bar 17, with the second
ending, would go the same way. The operation is refused before anything
changes:

  (apply-edit *hymn* op)
    -> invalid-edit: invalid edit #<set-time>: re-barring would remove a measure with a key, a repeat, an ending, a jump or a rehearsal mark
  (handler-case (apply-edit *hymn* op) (invalid-edit (c) (eq (invalid-edit-op c) op)))
    => t   ; the condition names the operation
  (multiple-value-bind (score changes)
      (handler-bind ((invalid-edit #'skip-edit))
        (apply-edit *hymn* op))
    (list (eq score *hymn*) (change-set-empty-p changes)))
    => (t t)   ; SKIP-EDIT

========================================================================
== 10. Transposition
========================================================================
TRANSPOSE moves the notes, the key signatures and the chord symbols. The
spelling comes from music-theory 0.5.0. For an interval it is TRANSPOSE-PITCH
and TRANSPOSE-CHORD-SYMBOL. For a target key it is TRANSPOSE-TO-KEY, whose
letter moves at most three steps. Every note keeps its id and its accidental
display. A chord symbol loses its TEXT, so it prints from its parts.

Up a major second: G major becomes A major.

  (interval-name m2) => "M2"
  (key-name (bar-key up 0)) => "A major"
  before    N.C., G, G7/B@1/2, C, G, Em, D, D7/F#, G, G7/B@1/2, C, G, Em@1/2, D, G,
            D7, G, G
  after     N.C., A, A7/C#@1/2, D, A, F#m, E, E7/G#, A, A7/C#@1/2, D, A, F#m@1/2, E,
            A, E7, A, A

  bar  id     time  melody                  bass               chords
    7  m-a    3/4   E5:h.~                  E2:h.              E
    8  m-b    3/4   E5:h' C#5:q[mf]         G#2:h.             E7/G#

  (list (length (change-set-created changes)) (length (change-set-removed changes))
        (length (change-set-modified changes)))
    => (0 0 77)   ; 58 notes and chord notes, 18 chord symbols, bar 0's key
  (tie-end (note-tie (melody-at up 7 0))) => "e-20"   ; the tie still joins E5 to E5
  (check-score up) => nil

To a key. With TO-KEY, every pitch goes from the key in force at FROM (G major)
to TO-KEY by TRANSPOSE-TO-KEY: it keeps its scale degree and alteration. Chord
symbols move the same way. G major to Ab major:

  (key-name (bar-key ab 0)) => "Ab major"
  after     N.C., Ab, Ab7/C@1/2, Db, Ab, Fm, Eb, Eb7/G, Ab, Ab7/C@1/2, Db, Ab, Fm@1/2,
            Eb, Ab, Eb7, Ab, Ab

  bar  id     time  melody                  bass               chords
    7  m-a    3/4   Eb5:h.~                 Eb2:h.             Eb
    8  m-b    3/4   Eb5:h' C5:q[mf]         G2:h.              Eb7/G
   17  m-m    3/4   Ab4:h.^                 <Ab2 Eb3>:h.^      Ab

  (check-score ab) => nil

Up an augmented unison, G major becomes G# major, with eight sharps. That is
not one of the 30 keys, and PARSE-KEY refuses it. For each key it moves,
TRANSPOSE takes (choose-enharmonic-key K' :max-accidentals 7). That returns K'
when K' is one of the 30 keys, and otherwise the one of them that sounds the
same. Then it respells the notes and chord symbols from K' to that key. So
the result is Ab major, spelled for Ab major, not G# major with eight sharps:

  (parse-key "G# major")
    -> invalid-key: invalid-key "G# major": signature beyond seven sharps or flats
  (key-name (choose-enharmonic-key g-sharp :max-accidentals 7))
    => "Ab major"   ; 4 flats, not 8 sharps
  (key-signature (choose-enharmonic-key g-sharp)) => -4
  (key-name (choose-enharmonic-key (parse-key "F# major")))
    => "F# major"   ; 6 sharps: kept
  (key-name (choose-enharmonic-key (parse-key "C# major"))) => "Db major"
  (key-name (choose-enharmonic-key (parse-key "C# major") :max-accidentals 7))
    => "C# major"
  (key-name (bar-key a1 0)) => "Ab major"
  (bar-text a1 0 8) => "Eb5:h' C5:q[mf]"
  (score-equal a1 ab) => t   ; the same score as TO-KEY Ab major

A range. FROM and TO limit the transposition to bars 9-15, the second half of
the verse, up a major second. Bar 9 gets A major as its own key. Bar 16, the
measure after TO, keeps its signatures: it gets G major as its own key, so the
endings are still in G. Chord symbols move only inside the range:

  bar  key       own key  melody
    8  G major   -        D5:h' B4:q[mf]
    9  A major   yes      E5:h C#5:e( E5:e)
   10  A major   -        C#5:h A4:q
   11  A major   -        E4:h F#4:q

   15  A major   -        C#5:h B4:q

  chords    N.C., G, G7/B@1/2, C, G, Em, D, D7/F#, A, A7/C#@1/2, D, A, F#m@1/2, E, A,

========================================================================
== 11. Views: EXTRACT-PART, CONDENSED-VIEW and UNFOLD
========================================================================
A view is a pure function of a source score. It returns a new score and an ID
MAP, an FSet map from each view id that comes from the source to the source id.
Elements carried over unchanged are the source's own objects (EQ). Elements a
view makes, and every copy after the first, get minted ids that continue the
source's counter. The view of a valid score is valid.

EXTRACT-PART takes a part or a voice. The view keeps the source's measure map,
every chord symbol, and the spanners whose two ends it keeps. The melody voice
on its own:

  part p-o "Melody", staves treble
    voice v-r   Melody   staff 1  stem -      D4:q[mp] | G4:h B4:e G4:e | B4:h A4:q | G4:h E4:q | ...

  (eq (voice-at melody 0) (voice-at *hymn* 0))
    => t   ; already staff 1, stem NIL: the same voice
  (list (fset:size (score-spanners melody)) (fset:size (score-chord-symbols melody)))
    => (5 18)   ; the five slurs, every chord symbol
  (list (fset:size id-map) (id-map-identity-p id-map))
    => (147 t)   ; every id maps to itself
  (check-score melody) => nil

The bass voice moves from staff 2 to staff 1 of a part with one staff, the bass
clef. The voice is rebuilt, since its STAFF changed, but its events are the
source's. No slur has both ends in the bass:

  part p-o "Bass", staves bass
    voice v-3h  Bass     staff 1  stem -      r:q | G2:h.[mp] | G2:h B2:q | C3:h. | ...

  (every #'eq (voice-events (voice-at bass 0)) (voice-events (voice-at *hymn* 1)))
    => t
  (fset:size (score-spanners bass)) => 0
  (multiple-value-bind (whole)
      (extract-part *hymn* (element-id (fset:first (score-parts *hymn*))))
    (list (score-equal whole *hymn*)
          (eq (fset:first (score-parts whole)) (fset:first (score-parts *hymn*)))))
    => (t t)   ; the whole part: the hymn again
  (extract-part *hymn* "v-zz")
    -> unknown-element: no element with id "v-zz"
  (multiple-value-bind (view)
      (handler-bind ((unknown-element (lambda (c) (use-value (voice-id *hymn* 1) c))))
        (extract-part *hymn* "v-zz"))
    (voice-name (voice-at view 0)))
    => "Bass"   ; USE-VALUE: another id

CONDENSED-VIEW puts up to four voices on two staves, the hymnal reduction. The
hymn has two voices, so this uses a four-part fragment of OLD HUNDREDTH: the
first line of Louis Bourgeois's melody (1551), with an alto, tenor and bass
written for this demo. It is an open score, with one part per voice:

  part p-4 "Soprano", staves treble
    voice v-6   Soprano  staff 1  stem -      G4:h | G4:q F#4:q E4:q D4:q | G4:q A4:q B4:h

    voice v-h   Alto     staff 1  stem -      D4:h | D4:q D4:q B3:q B3:q | D4:q D4:q D4:h
  part p-q "Tenor", staves treble-8vb
    voice v-s   Tenor    staff 1  stem -      B3:h | B3:q A3:q G3:q G3:q | G3:q F#3:q G3:h
  part p-11 "Bass", staves bass
    voice v-13  Bass     staff 1  stem -      G2:h | B2:q D3:q E3:q G2:q | B2:q D3:q G2:h

  (check-score chorale) => nil
  (score-id-counter chorale) => 47

and alto share staff 1, tenor and bass share staff 2. The upper voice of each

  part p-1c (no name), staves treble bass
    voice v-6   Soprano  staff 1  stem up     G4:h | G4:q F#4:q E4:q D4:q | G4:q A4:q B4:h
    voice v-h   Alto     staff 1  stem down   D4:h | D4:q D4:q B3:q B3:q | D4:q D4:q D4:h

    voice v-13  Bass     staff 2  stem down   G2:h | B2:q D3:q E3:q G2:q | B2:q D3:q G2:h

  (list (element-id part) (mapcar #'element-id (part-staves part)))
    => ("p-1c" ("st-1d" "st-1e"))   ; serials 48-50
  (every #'eq (all-events condensed) (all-events chorale))
    => t   ; every event is the source's
  (every #'eq (fset:convert 'list (score-measure-map condensed))
         (fset:convert 'list (score-measure-map chorale)))
    => t   ; the source's measures
  (list (fset:size id-map) (id-map-identity-p id-map))
    => (39 t)   ; 3 measures, 4 voices, 32 notes; not the part or staves
  (check-score condensed) => nil
