== 1. Build a type-1 SMF in code and write it to bytes
==============================================================================
Twinkle, Twinkle, Little Star in C major, 4/4, two phrases of two bars, at 480 ticks per
quarter note. Each track is built as (tick . event) pairs at absolute ticks, and
TRACK-FROM-ABSOLUTE turns the list into delta times and appends the end of track
(section 4). Events are immutable structs made by MAKE-<TYPE> keyword constructors.

(make-smf :format 1 :division 480 :tracks (list tempo melody bass)):
  track 0   8 events  tempo, meter, key, title and markers
  track 1  47 events  flute on channel 0: track name, program, volume, pan, one lyric per note
  track 2  37 events  bass on channel 1: track name, program, volume, pan, root and fifth

(write-smf smf nil) returns 527 bytes as a (SIMPLE-ARRAY (UNSIGNED-BYTE 8) (527)).

The header chunk, 14 bytes, big-endian:
  offset  bytes         field
       0  4D 54 68 64   "MThd"
       4  00 00 00 06   header length 6
       8  00 01         format 1
      10  00 03         3 track chunks follow
      12  01 E0         division: 480 ticks per quarter note

The first track chunk, the tempo track: "MTrk", its length, then each event as
a delta time (a variable-length quantity) and the event's bytes. Meta events are
FF <type> <length> <data>.

(30 * 128 + 0). 600000 us is 09 27 C0 and 750000 us is 0B 71 B0 (u24). The time
signature stores the denominator 4 as its base-2 logarithm, 02.

== 3. Running status
==============================================================================
With running status (the default, as mido writes) a channel event leaves out its
status byte when the event before it in the track is a channel event with the same
status. A meta, sysex or escape event in between resets it. :RUNNING-STATUS NIL
writes every status byte.

  track    :running-status t   nil   saved   repeated statuses
      0                   91    91       0           0
      1                  256   257       1           1
      2                  142   159      17          17
  file                   527   545      18

The melody saves one byte (pan after volume): every note-on follows a lyric, a meta
event, and every note-off follows a note-on. The bass plays two notes at once, so
the second note-on and the second note-off of each pair go without a status byte.
Its first events, encoded both ways:

  event                                        running status t   nil
  control-change  ch 1  cc 7 (volume) = 90     00 B1 07 5A        00 B1 07 5A
  control-change  ch 1  cc 10 (pan) = 80       00 0A 50           00 B1 0A 50
  note-on         ch 1  C2   vel 70            00 91 24 46        00 91 24 46
  note-on         ch 1  G2   vel 70            00 2B 46           00 91 2B 46
  note-off        ch 1  C2   vel 64            87 40 81 24 40     87 40 81 24 40
  note-off        ch 1  G2   vel 64            00 2B 40           00 81 2B 40
  note-on         ch 1  C2   vel 70            00 91 24 46        00 91 24 46
  note-on         ch 1  G2   vel 70            00 2B 46           00 91 2B 46

Both files read back to the same events, and the one without running status,
written again with the default, gives the shorter file byte for byte.

== 4. Absolute time: ticks, merging, the tempo map, seconds
==============================================================================
TRACK-TO-ABSOLUTE pairs each event with its absolute tick, the sum of the deltas
so far. The first ten of the melody:
  (   0 . track-name      "Melody")  delta 0
  (   0 . program-change  ch 0  73 (Flute))  delta 0
  (   0 . control-change  ch 0  cc 7 (volume) = 100)  delta 0
  (   0 . control-change  ch 0  cc 10 (pan) = 40)  delta 0
  (   0 . lyric           "Twin-")  delta 0
  (   0 . note-on         ch 0  C4   vel 80)  delta 0
  ( 480 . note-off        ch 0  C4   vel 64)  delta 480
  ( 480 . lyric           "kle")  delta 0
  ( 480 . note-on         ch 0  C4   vel 80)  delta 0
  ( 960 . note-off        ch 0  C4   vel 64)  delta 480
TRACK-FROM-ABSOLUTE turns them back into the same track (EQUALP). It sorts by tick
with a stable sort, so events at the same tick keep their input order. Given the
pairs in reverse, the events at tick 480 come out reversed too:
  in order:   note-off        ch 0  C4   vel 64
              lyric           "kle"
              note-on         ch 0  C4   vel 80
  reversed:   note-on         ch 0  C4   vel 80
              lyric           "kle"
              note-off        ch 0  C4   vel 64

the note-ons at the same tick, as the builders in section 1 do.

== 6. Bad values: MIDI-ENCODE-ERROR
==============================================================================
At SBCL's default safety the constructors check the slot types themselves:
  (make-note-on-event :key 128)            -> TYPE-ERROR
  (make-note-on-event :delta #x10000000)   -> TYPE-ERROR

Values a slot type lets through are checked by WRITE-SMF, which checks the whole
SMF before it writes a byte and signals MIDI-ENCODE-ERROR with the track and the
element at fault:
  a sysex data byte 300                track 1   sysex-event            sysex-event-data holds an element that isn't an octet
  a lyric of U+266A (code above 255)   track 1   lyric-event            text has a character whose code is above 255
  a 4/6 time signature                 track 0   time-signature-event   time signature denominator 6 is not a power of two from 1 to 2^255
  an end of track mid-track            track 2   end-of-track-event     end-of-track event before the last event of the track
  a (tick . event) pair as an element  track 1   cons                   track element is not a MIDI-EVENT
  an unknown meta event of type 51     track 0   unknown-meta-event     unknown meta event with the known type byte #x51
  format 0 with three tracks           track -   -                      format 0 with 3 tracks, not 1
The report of the first: MIDI encode error in track 1: sysex-event-data holds an element that isn't an octet (#S(MIDI-PROTOCOL:SYSEX-EVENT :DELTA 0 :DATA #(240 126 127 9 300 247)))
Writing that SMF to a file signals before the file is opened: it does not exist
afterwards (probe-file -> NIL).

== 7. Files and streams
==============================================================================
(write-smf smf path) wrote harness/midi/twinkle.mid, 527 bytes. (read-smf path)
reads it back: T.
It is byte-identical to the copy committed with this demo: T.

Streams: the type-0 and the type-1 file written one after the other to one
octet stream (493 + 527 bytes). READ-SMF on a stream stops after the last track
chunk it needs, so two calls read them back: format 0 at position 493, then
format 1 at position 1020, and then the stream is at its end (:EOF).
