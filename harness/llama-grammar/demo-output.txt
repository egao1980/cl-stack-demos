== 2. Grammar-constrained COMPLETE (#17)
========================================================================
llama-cpp 0.2.0 called llama_sampler_accept after llama_sampler_sample, which
already accepts the token: the grammar saw every piece twice and threw
"Unexpected empty grammar stack after accepting piece: y" on the first token.
The shim was C, so the C++ exception ran into std::terminate: SIGABRT, LDB.
0.2.1 accepts each token once; once the grammar is complete llama.cpp only allows
end-of-generation, so the text is a sentence of the grammar.

  grammar                                root ::= ("yes" | "no")
  ok       complete "The cat" :grammar: T
    →                                    (:OK "yes")
  ok       complete "Is the sky blue?" :grammar: T
    →                                    (:OK "no")
  ok       complete "Once upon a time" :grammar: T
    →                                    (:OK "no")
  grammar                                root ::= "The answer is " ("yes" | "no") "."
  ok       complete "Question:": "The answer is yes."

== 5. Dead ends and C++ exceptions become LLAMA-ERROR (#17)
========================================================================
No token's piece starts with NUL, so this grammar rules out every candidate.
llama_sampler_sample picks one anyway (greedy keeps candidate 0) and llama.cpp's
accept throws; 0.2.0 aborted here. The 0.2.1 shim applies the grammar itself,
drops what it rules out, and sees that nothing is left: a grammar dead end.

  complete :grammar "root ::= \"\\x00\"" llama-cpp error (RUNTIME): llama_stack_complete_ex: grammar dead end: the grammar allows no token after 0 generated token(s) "". llama.cpp masks end-of-generation tokens until the grammar is complete, so a grammar that names one (<|im_end|>, </s>) cannot finish; end the grammar where the text ends
  ok       a LLAMA-ERROR: :LLAMA-ERROR
  ok       status RUNTIME, "grammar dead end": T
  undefined rule                         llama-cpp error (INVALID): llama_stack_complete_ex: grammar parse failed
  ok       status INVALID: T
libllamastack is C++ behind the C ABI: every exported function catches what
llama.cpp throws and returns LLAMA_STACK_RUNTIME with the text.
llama_stack_guard_selftest throws on purpose, inside that guard:

  ok       std::runtime_error, std::bad_alloc, a non-std exception: ((:RUNTIME "C++ exception: guard selftest") (:RUNTIME "out of memory")
 (:RUNTIME "unknown C++ exception"))

== 6. Exit with a live engine (#18, #20)
========================================================================
An engine kept in a global outlives the Lisp side: C exit() destroyed
ggml-metal's device list under the model's residency sets and
ggml_metal_device_free aborted (GGML_ASSERT, SIGABRT) instead of exiting with the
program's code. The finalizers never helped: they closed over the engine, so it
was never garbage (#20). 0.2.1 frees what is still live from sb-ext:*exit-hooks*
(FREE-LIVE-HANDLES: grammars, then engines).

  child: engine in a global, then (sb-ext:exit :code 3) exit 3
  ok       exit code, no abort: (3 NIL)
  child: engine in a global, then (error "boom") exit 1
  ok       exit code, no abort: (1 NIL)
  ok       free-live-handles (one engine, one grammar here): 2
  ok       again: nothing left: 0
  ok       the handles read as freed: (T T)

== 7. A vocabulary whose token 0 is end-of-generation (#17, round 2)
========================================================================
SmolLM2's token 0 is <|endoftext|>. When the grammar rules out every token,
the forced pick is token 0, an end-of-generation token, and llama.cpp's grammar
accept calls GGML_ABORT (abort(), not an exception: no guard catches it).
A grammar that names the end-of-turn token gets there after one word:
llama.cpp masks EOG tokens until the grammar is complete, so <|im_end|> is never
allowed. The 0.2.1 shim stops at the dead end before it picks.
