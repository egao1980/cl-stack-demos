# Documents demo: PDF, DOCX, XLSX, YAML, .env and images

`harness-demos-documents` shows five gaps found while writing the [Python to Common Lisp](https://egao1980.github.io/python-to-cl/) pages, each fixed in its owning library and published to GHCR:

| Section | Issue | Fixed in |
|---------|-------|----------|
| 1. PDF text with no password | [doc-extract-backend-pdf#9](https://github.com/egao1980/doc-extract-backend-pdf/issues/9) | doc-extract-backend-pdf 0.1.5 (this demo runs 0.2.0) |
| 2. DOCX and XLSX | [doc-extract-protocol#6](https://github.com/egao1980/doc-extract-protocol/issues/6), [compression-protocol#10](https://github.com/egao1980/compression-protocol/issues/10) | doc-extract-protocol 0.4.0 on compression-protocol 0.5.1, xml-backend-native 0.1.1 |
| 3. YAML block output without trailing blanks | [yaml-protocol#7](https://github.com/egao1980/yaml-protocol/issues/7) | yaml-protocol 0.2.2 |
| 4. `.env` files and typed settings | [cl-stack-config#8](https://github.com/egao1980/cl-stack-config/issues/8) | cl-stack-config 0.3.0 |
| 5. Image editing operations | [image-protocol#2](https://github.com/egao1980/image-protocol/issues/2) | image-protocol 0.2.0 |

Each section ends with a cross-read by the Python library the page compares against: pypdf, python-docx and openpyxl, PyYAML, python-dotenv and Pillow, run through `uv`. The results are checked, not just printed: the summary line counts them (113 checks with uv, 53 without, 0 mismatched in the committed run). The code is in [`src/`](src/), one file per section, and the Python side in [`crosscheck/`](crosscheck/). [`demo-output.txt`](demo-output.txt) is the output of the last run (macOS arm64, SBCL 2.6.9, home paths written as `~`).

## Run

```bash
cd harness/documents
cl-repo run -- sbcl --non-interactive --no-userinit --eval '(require "asdf")' \
  --eval '(asdf:load-system "harness-demos-documents")' \
  --eval '(harness-demos-documents:run-demos)' > demo-output.txt 2>&1
```

It needs SBCL and `cl-repo`. libpdfium (pdfium-binaries, BSD-3-Clause) and stb come with the native overlays of doc-extract-backend-pdf and image-backend-stb, for linux amd64 and arm64, darwin arm64 and windows amd64. The cross-reads also need [uv](https://docs.astral.sh/uv/) on `PATH`; on its first run uv downloads the pinned Python packages from PyPI. Without uv, each cross-read prints a note and is skipped. With a warm cache the command takes about 8 seconds on an M-series Mac, most of it the seven uv subprocesses. `run-demos` returns `NIL` if a check fails or a section stops on an error, and the harness-demos workflow then exits 1.

The inputs are in [`fixtures/`](fixtures/) ([PROVENANCE](fixtures/PROVENANCE.md)): `report.pdf` (reportlab) and its AES-256 copy `report-locked.pdf` (pypdf), `report.docx` (python-docx), `report.xlsx` (openpyxl), all written by [`fixtures/make-fixtures.py`](fixtures/make-fixtures.py), plus the hand-written `app.env` and `app.toml`. The images and every damaged file are made by the demo itself.

## What each section shows

1. **PDF text with no password.** `(make-pdf-doc-extract-backend)` now passes a NULL password to libpdfium. In 0.1.4 it passed `NIL` to a `:string` argument, so every unencrypted PDF failed with "NIL is not a Lisp string or pointer." `extract-text` reads `report.pdf` from a pathname and from octets, and gives the same 96 characters both ways. `extract-metadata` gives the title, the author and `:page-count 2`. `:password ""` gives the same text. The locked copy signals `doc-extract-error` with no password or a wrong one, and the right password gives the text of `report.pdf`. `:password 42` is a `type-error`. pypdf 6.1.1 gives the same words, refuses the locked copy without its password (`FileNotDecryptedError`), and reads it with the password.
2. **DOCX and XLSX.** 0.3.1 read the openpyxl workbook as `""`, ran the python-docx table cells together (`regionq2North135`), split runs mid-word and kept `&amp;`. Now the DOCX gives one line per paragraph and table row, with cells separated by Tab. `extract-sections` gives `("Quarterly report" 1) ("Totals" 2) ("Notes" 2)`, and the `extract-document` outline shows the heading tree with a 3 × 3 `table-block`. The XLSX gives one section per sheet (`Totals`, `Notes`) holding a table cropped to the used range. The formula cells have no cached value, so they are empty, as `openpyxl.load_workbook(data_only=True)` gives `None`. Then the demo rebuilds `report.docx` with compression-protocol's stored zip writer, the way zipfile's default `ZIP_STORED` writes it, and adds `report.xlsx` as `word/embeddings/Microsoft_Excel_Worksheet.xlsx`. The package is 835,438 bytes and holds two end-of-central-directory records. compression-protocol 0.5.0 took the inner one ("corrupt zip central directory"). 0.5.1 takes the last one, as zipfile does, and the text equals the original's. Three damaged uploads signal `doc-extract-error` with the underlying condition as `doc-extract-error-cause`. The first half of the file and a text file named `.docx` give `archive-error`, and one inverted byte in `word/document.xml`'s deflate data gives `compression-error`. python-docx 1.2.0 and openpyxl 3.1.5 agree on the paragraphs, the table cells, both sheets' values and the stored package. On the damaged files they raise `PackageNotFoundError` and `zlib.error`.
3. **YAML block output.** Every line is printed with a `$` at its end. yaml-protocol 0.2.1 wrote `langs: ` (with a trailing space) for `{name: Ada, langs: [lisp, ml]}`. 0.2.2 writes `langs:`, for that document, a deeper one with nested mappings and sequences, `[]` and null, and a graph with shared objects (`- &id1`, `langs: &id2`, `teaches: *id2`, `- *id1`). Each decodes back `equalp`, and the alias decodes to the same object (`eq`). PyYAML 6.0.3 loads all three to the same data and finds no trailing blank. Its own `safe_dump` is printed next to each. One difference showed up: the text has no final newline, where PyYAML's dump ends with one ([yaml-protocol#11](https://github.com/egao1980/yaml-protocol/issues/11)).
4. **`.env` files and typed settings.** `read-dotenv` of `app.env` covers `export`, blanks around `=`, `${NAME}` and `${NAME:-default}` (file first, then `:environ`), escapes in double quotes, a multi-line PEM value, a comment after a blank, `#336699` inside a value, an empty value and a bare `APP_FLAG` (`NIL`, never set). python-dotenv 1.1.1's `dotenv_values` gives exactly the same pairs. A malformed line is skipped with a `dotenv-syntax-warning` (line 2), which `muffle-warning` silences. `load-dotenv` sets only the variables that are unset, unless `:override t`. `load-config` layers file < `.env` < environment, and `load-into` fills a `defschema`. Host and port come from `.env` (`"5432"` coerced to 5432), `max_connections` comes from the environment and `"true"` becomes `T`. Three bad values are reported in one `config-validation-error`. A Latin-1 file signals `config-parse-error` that names the path, where python-dotenv raises `UnicodeDecodeError`.
5. **Image editing operations.** The input (64 × 48 RGBA, opaque on the left, alpha growing downwards on the right) and a translucent logo are made in code and written as PNG by image-backend-stb. Hand-worked values are checked: crop, rotation direction, flip, thumbnail's 4:3, `fit-image` rounding, no enlarging, and `image-invalid-argument` for a crop past the edge and for 45°. Then the two inputs and 16 results go into a table: crop, rotate 90 / 180 / 270 / -90, both flips, resize to 37 × 23 with each of the five filters, an enlargement to 160 × 120, an RGB resize with `:reducing-gap 2`, a thumbnail and a composite. Each row has the SHA-256 of its pixels, and Pillow 11.3.0 gives the same pixels for every row. [`output/`](output/) holds the inputs and three of the results as PNG.

## Issues found

- [yaml-protocol#11](https://github.com/egao1980/yaml-protocol/issues/11): `:block` output ends without a final newline, where PyYAML's dump ends with one (yamllint `new-line-at-end-of-file`). Open.
- While this demo was written, cl-stack-config 0.3.0's ECL lane showed that ECL 26.5 signals nothing for a UTF-8 sequence cut short at the end of a file: it drops the sequence, so the Latin-1 file read as `APP_NAME=caf`. cl-stack-config now decodes `.env` octets with encoding-protocol's strict UTF-8 decoder, so every implementation signals `config-parse-error`. The fix was in place before 0.3.0 was published.
- Open follow-ups from the prosecutors, not shown here: [doc-extract-backend-pdf#17](https://github.com/egao1980/doc-extract-backend-pdf/issues/17) (concurrent extraction from several threads crashes SBCL, because PDFium is not thread-safe), [#18](https://github.com/egao1980/doc-extract-backend-pdf/issues/18) (no distinct condition for a missing or wrong password, so the demo shows only the message) and [#14](https://github.com/egao1980/doc-extract-backend-pdf/issues/14) (relative and wild pathnames). Also [doc-extract-protocol#7](https://github.com/egao1980/doc-extract-protocol/issues/7) (XLSX number formats and dates, DOCX lists, headers and footers), [yaml-protocol#10](https://github.com/egao1980/yaml-protocol/issues/10) (plain scalars that need quoting) and [image-protocol#6](https://github.com/egao1980/image-protocol/issues/6) (a pixel budget for `fit-image`).
