# engrave demo: engines, pages, id maps, timemaps and the PDF path

`harness-demos-engrave` is a tour of **engrave-protocol 0.1.0** (slice EN0) from GHCR, on score-protocol 0.3.0 and xml-protocol 0.1.0. The protocol turns a [score-protocol](../score/) score, or one of its views, into SVG pages whose element ids lead back to the score. It also gives a timemap for playback cursors and PDF through a printer. An engine does the rendering, behind the protocol.

**No native engine is published yet.** The first one is planned as a separate backend. So every section uses the reference `null-engine`, which draws one placeholder group per element and lays out no music. Everything around the engine is the real protocol: availability and `use-value`, layouts, views, the id map, page and system splitting, `skip-element`, the conformance checks, the timemap, and the printer path of `render-pdf`. The pages show the structure of a rendering, not engraved music. EN0 ships no PDF printer either, so section 10 shows only the two refusals.

The score is the first line of OLD HUNDREDTH ("All people that on earth do dwell": melody by Louis Bourgeois, 1551; words by William Kethe, 1561). It is an open score of four parts, one staff each, with lower parts written for the demo. It is in G major and 4/4 with a half-note pickup, marked Moderato with a quarter at 96. The last chord is slower ("rit.", a quarter at 72) and has a fermata in every part. Everything is in [`src/demo.lisp`](src/demo.lisp). [`demo-output.txt`](demo-output.txt) is the output of the last run, on macOS arm64 with SBCL 2.6.9. Home and temp paths in it are replaced with `~` and `<tmp>`. The run also writes [`old-hundredth.svg`](old-hundredth.svg), page 1 of the choral rendering.

## Run

```bash
cd harness/engrave
cl-repo run -- sbcl --non-interactive --no-userinit --eval '(require "asdf")' \
  --eval '(asdf:load-system "harness-demos-engrave")' \
  --eval '(harness-demos-engrave:run-demos)' > demo-output.txt 2>&1
```

It needs SBCL and `cl-repo`, and nothing else. The demo checks every printed result that has a known answer: 92 checks. `run-demos` returns `NIL` if any check fails or a section stops on an error.

## What each section shows

1. **Engines.** `null-engine` is named `"null"`, is available, and draws every element. `*engrave-engine*` is `NIL`, so `(ensure-engine nil)` signals `engine-unavailable` inside a USE-VALUE restart. Binding the variable or answering the restart gives an engine. `unloaded-engine` (in `demo.lisp`) stands in for an engine whose native library did not load: `engine-available-p` is false. Rendering with it signals before anything is drawn, and USE-VALUE swaps the null engine in for the whole call. A string as the engine is a `type-error`.
2. **Layout.** `make-layout` defaults to A4, 10 mm margins, scale 100 and `:auto` breaks. The section lists the named page sizes (letter is 215.9 × 279.4 mm, kept as exact rationals), four margins, and a plist through `ensure-layout`. Eight values are refused as `invalid-render-option`: an unknown size, a length that is not whole tenths, a float, margins wider than the page, scale 0, a repeated break id, an odd plist, and an unknown key.
3. **Pages.** `render-svg` on A4 gives one page with one system of three measures. The page is an xml-protocol tree, not a string: an `svg` root in the SVG namespace, with `viewBox="0 0 2100 2970"` in tenths of a millimetre and a size of `210mm` × `297mm`. The first 40 elements are printed as a tree. Page 1 opens with the parts group (each part with its name, staff and voice), then the system, its measures and, in each measure, the tempo mark and every voice's notes with their lyrics. The page has 71 SVG elements and 62 ids. They are all unique NCNames, and `system.1` is the only id the engine made up. `find-svg-element` finds the soprano's first note under its own id. `element-kind` gives the group classes. The same input gives the same bytes.
4. **The id map.** It maps each of the 61 element ids to `((1 . its own id))`: the page and SVG id where the element is drawn. A table shows a measure, a tempo mark, a part, a staff, a voice, a note, a lyric and a fermata.
5. **Page splitting and system breaks.** On A5 at scale 200, one measure fits a line and two systems fit a page, so the line takes three systems on two pages. The id map puts bar 2 on page 2, and parts, staves and voices on page 1. `:page 2` returns that page alone, byte for byte the same, with the same whole id map. Page 3 and page 0 are refused. `:system-breaks` with bar 1's id gives two systems. The pages' `systems` lists are the break plan: fed back as breaks, they give the same bytes. An unknown measure id is refused.
6. **Views.** `:condensed` draws `condensed-view`: one part, a treble and a bass staff, and four voices with stems up and down. The id map keeps the source ids and leaves out the 4 source parts and 4 staves (53 keys). `:parts ("P1" "P4")` draws the outer voices (37 keys). Both pass `check-engraving`. `:view :piano` and an unknown part are refused.
7. **Unsupported notation.** `(make-null-engine :unsupported '(fermata tempo-mark))` signals `unsupported-notation` for the two tempo marks and the four fermatas, in document order, each inside `skip-element`. score-protocol's symbol is the one its MusicXML reader uses. Skipped elements map to `()`, have no group, and `check-engraving` reports them as `:not-drawn`. When the voices themselves are refused, 4 conditions are signalled and 48 elements are not drawn: the voices, their 32 notes, 8 lyrics and 4 fermatas.
8. **Conformance.** `check-engraving` returns `()` for the null engine's renderings. It reports pages out of order (`:page-number` and `:systems`), an element missing from the id map, a key that is no element, and a drawing on a page that does not exist (`:dangling-ref`).
9. **Timemaps.** `render-timemap` gives 9 entries, printed with exact milliseconds, the tempo, and the notes that start and end at each onset. A quarter is 625 ms at 96. The last chord is at 72 and ends at 20000/3 ms (6666.67), and the fermatas add no time. `score-timemap` gives the same, since there is no repeat, and `check-timemap` passes. With a repeat from the pickup to the final bar, the unfolded timemap has 17 entries. Each note appears once per pass under its own id. At the turn, pass 1's last chord ends where pass 2's first starts, back at 96, and the whole ends at 40000/3 ms. With `:unfold nil` the timemap is the score as written. `check-timemap` reports the written timemap checked as unfolded (32 `:event-count` issues), two swapped entries (`:onset-order`, `:off-before-on`), and a part id among the events (`:unknown-event`). A negative onset and a non-score argument are `type-error`s.
10. **PDF.** `*pdf-printer*` is `NIL`, and `render-pdf` without a printer signals `printer-unavailable`, with USE-VALUE live in the handler. `svg-text-printer` (in `demo.lisp`) returns the pages' SVG text as octets. The protocol refuses it with `engine-render-error` ("the printer returned no PDF"), whether it is passed as `:printer` or through USE-VALUE.
