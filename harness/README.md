# Harness demos

Runnable demos of the coding-agent harness work (plan: cl-workspace `docs/HARNESS-PLAN.md`), run against the **published GHCR packages** — evidence that each feature works, and a bug finder: anything a demo trips over is filed on the owning repo, not worked around.

Five cl-repo projects, one per area. Each `demo-output.txt` is the captured output of the last run (home and temp paths replaced with `~` / `<tmp>`).

| Project | System | Packages demonstrated |
|---------|--------|-----------------------|
| [`data/`](data/) | `harness-demos-data` | diff-protocol 0.3.0 (engine extension API), diff-backend-lisp-source 0.1.0, revision-protocol 0.3.0, sql-orm 0.3.0, sql-migrate 0.2.1 |
| [`fs/`](fs/) | `harness-demos-fs` | cl-stack-pathlib 0.6.1, process-protocol 0.4.0, process-backend-uiop 0.3.1, revision-backend-git 0.2.0, revision-backend-jj 0.2.0 |
| [`agent/`](agent/) | `harness-demos-agent` | ai-agent-protocol 0.10.0, agent-tools 0.2.0 (file and shell tools), tui-protocol 0.2.0 (widgets), tui-markdown 0.1.0, tui-backend-tty 0.1.1, llm-protocol-openai 0.4.0 |
| [`code/`](code/) | `harness-demos-code` | cl-stack-code 0.2.0 (`-p` headless CLI through `run-cli`; H3b interactive mode on tui-backend-terminal 0.1.0), cli-protocol 0.2.1, ai-agent-protocol 0.12.0 (headless denial), tui-markdown 0.2.0, http-backend-async 0.2.21 |

## Run

From a project directory (dependencies come from GHCR through `cl-repo`; `--no-userinit` keeps a personal `~/.sbclrc` out of the image):

```bash
cd harness/data   # or fs, agent, code, image
cl-repo run -- sbcl --non-interactive --no-userinit --eval '(require "asdf")' \
  --eval '(asdf:load-system "harness-demos-data")' \
  --eval '(harness-demos-data:run-demos)' > demo-output.txt 2>&1
```

Needs: SBCL via Roswell, `cl-repo`, `git` (≥ 2.43; ≥ 2.56 once revision-backend-git 0.4.0 resolves) and `jj` 0.47.1 for `fs/`. The prompt-cache step in `agent/` talks to a local LM Studio (`http://127.0.0.1:1234/v1`, token from `LM_API_TOKEN` in the workspace `.env`; it is never printed) and reports that it was skipped when no server is reachable. `code/` uses the same server and token when a model is loaded, and a scripted mock provider otherwise (its interactive Demo f always runs on a scripted streaming mock, plus one LM Studio turn when a model is there). `image/` spawns Swank images with `ros +Q run` (lisp-mcp's default `repl-spawn` command; swank and slynk come from cl-repo as `:ci :with` install roots) and runs its real-model step only when LM Studio answers.

## What each set shows

- **data** — unified diffs, three-way merge with conflict markers (default and `:diff3`), tree diffs with rename and mode changes, parsing real `git diff` output and applying / inverting it; a revision DAG with tags and as-of, a ref conflict resolved through the `retry` restart, plans and drift on a target, merge projections resolved with `take-ours`, composite restore (now with a caller `:id`); complete schema diffs and a SQLite table rebuild that keeps rows; migrations with offline SQL and a failing step that is both `step-failed` and `sqlite:sqlite-error`, resumed with `retry-step`.
  - **Demo 5, diff-backend-lisp-source** — a real file, process-protocol's `src/protocol.lisp` at 0.3.0 and 0.4.0 (committed under [`data/fixtures/`](data/fixtures/)): its top-level forms as units (header comments travel with their form), the 0.3.0 → 0.4.0 diff at `:summary` / `:changes` / `:content` (form adds, nested leaf edits such as `defun kill/2`), `unified-patch` with a path, byte-for-byte apply / invert / `:sexp` round trip; a comment edit, a rename (`alive-p` → `live-p`) and a move; a three-way merge of the real 0.4.0 change with edits to other forms (clean, symmetric) and against an edit of the same `defun kill` (one conflict, the two sides rendered with the `:text` engine); `lisp-source-unreadable` falling back through `use-text-diff`.
  - **Demo 6, diff-protocol 0.3.0 engine API** — an `:env` engine written in the demo (states are alists of strings, not text) registered with `register-diff-engine`, with `apply-change` and `render-unified-content` only: `:unified` of its own diffs, `parse-diff :sexp` finding it by name, diff-protocol's `skip-change` restart on a stale state, the default `merge-states` (one clean key, one conflict), and `.env` files in a tree diff rendered as hunks instead of `Binary files … differ`.
- **fs** — ranged reads, compare-and-swap writes with restarts, `.gitignore` walk / grep, content-addressed snapshots and restore, a sandboxed area seeing an external shell edit and committing past a conflict; binary process output, env merge vs replace, octet streams, timeouts; the git backend (commits, refs, diffs, a working copy whose drift is captured without touching the worktree or index, a read-only revision filesystem) and the jj backend (change ids across rewrites, as-of via the operation log, conflicted revisions).
  - **Demo 5, cl-stack-pathlib 0.6.1** — fnmatch globs (`?`, `[0-9]`, `[!0-9]`, escaped `\[x\]`, `**`, `rglob`) giving the same results on the local and the memory filesystem, `match-p`; probes on a file, a directory, links to each, a dangling link and a link cycle (`stat(2)` vs `lstat(2)` views, `symlink-loop` as a `path-error`). The `rglob` checks in Demo 1 now pass (cl-stack-pathlib#28 fixed in 0.6.0).
  - **Demo 6, process-protocol 0.4.0** — `supports-p`, `process-pid`; a shell whose background child (the grandchild) survives a plain `kill` but is stopped by `:process-group t` + `kill :tree t` (both in the shell's process group, checked with `ps -o pgid=`); `run :process-group t :timeout 1` whose grandchild never writes its marker; `kill :tree t` on a handle without a group signalling `process-group-error` with a `continue` restart.
- **agent** — "always allow" approvals saved to a rule store and reject-all-pending on a mock-model agent run; the seven file tools (diff previews, actionable failures, root escapes refused, permission resources); widgets on the headless terminal (text input with wide characters and paste, a permission dialog, a follow-tail viewport with spinner and status line); the real-terminal backend on a pty with `stty -g` identical before and after; `prompt_cache_key` sent to LM Studio and the reported usage.
  - **Demo 6, tui-markdown 0.1.0** — a model answer (headings, emphasis, strong, strike, inline code, a link with OSC 8 hyperlink, nested and ordered lists, a code block, an aligned table with wide characters, a quote) parsed to its AST and rendered at 60 and 34 cells in a viewport on the headless driver (the screen text is in the output, with per-run styles); a `markdown-stream` fed in chunks whose committed lines never change; a unified diff with line numbers, `⋮` between hunks and a word-level highlight, and a split layout from a diff-protocol value.
  - **Demo 7, agent-tools 0.2.0 shell tools** — foreground `bash` on the pty executor (ANSI and progress-bar cleaning, stderr merged, `[exit code 3]`, `workdir`, the `+shell-environment+`, stdin at EOF), the head + tail output cap, an unhandled timeout (killed after 0.8 s) and the `shell-timeout` restarts (`continue`, then `run-in-background`); a background job driven with `job_output`, `job_input` (a `read` answered), `job_list`, `job_kill`; the scanner's resources for ten command lines (`cd` tracking, writes, `*` for what it cannot model); a mock-model run where `ls` is allowed, `ls && rm …` is refused by `("bash" "program:rm" :deny)` with its feedback, a background job completes, and an undecided command asks. An allow on `program:ls` alone leaves `bash:ls src` undecided (it asks), so the run allows both `bash:ls*` and `program:ls`; that is the documented rule ("every resource must be decided").

- **code** — cl-stack-code 0.2.0. Demos a–e: the headless `cl-stack-code -p` CLI, driven through `run-cli` with an argv on small temporary git-rooted projects. The model is a loaded LM Studio model when the server answers (picked from `GET /v1/models`: a coder model first, then one LM Studio marks `tool_use`; this run: `qwen3.5-2b`), else a scripted mock provider; the output says which one ran. When the real model does not show a step's point (no answer, no edit, no write attempt), the same argv runs again on the mock, labelled as such. Real-model output varies run to run.
  - **a** — `--output-format text`: the model reads `notes.txt` and answers; stdout is just the answer, exit 0.
  - **b** — `--output-format stream-json --allowed-tools 'edit(greeting.txt)'`: the whole event stream (`system` init, `assistant` per step with usage, `tool_use`, `tool_result` with the edit's diff, `text_delta` folded, `result` last), and the file changed on disk without an approval.
  - **c** — default mode, no rule for `write`: the write is refused headless, the model gets a `tool_result` with status `denied` and the feedback naming `--allowed-tools`, the file is not created, and the run still ends with a `result` (here `error_max_turns`, the small model kept looking) listing the call in `permission_denials` with reason `headless`.
  - **d** — layered settings: user `settings.json`, project `.cl-stack-code/settings.json`, local `settings.local.json` and the flags, each layer as parsed, the merge (last scalar wins, rule lists concatenated with duplicates dropped, `env` key by key with a `null` unset that a later layer sets again), the files read, the agent's rule list (mode base rules, allows, asks, denies), a bare deny hiding `job_kill`, and the `system` init event of a run on those files.
  - **e** — `AGENTS.md` discovery from `pkg/core/`: the user-level file, then the project root's `AGENTS.md` (its `CLAUDE.md` ignored), `pkg/CLAUDE.md` (the fallback), `pkg/core/AGENTS.md`; a blank file and one below the working directory are not in the startup set. Then the assembled system prompt: the base prompt, `# Environment`, each `<instructions path=…>` block and the appended text.
  - **f, interactive mode (H3b)** — the `code-program` from `make-code-program`, on tui-backend-terminal's headless driver over the pure-Lisp emulator, as cl-stack-code's program tests drive it; the model is a scripted streaming mock (provider `tui-mock`, word-sized text deltas) whose steps can wait at a gate, so every screen is exact. Each screen is printed row by row. **f1** the first screen at 120 × 12: empty transcript, `─` rule, the input placeholder, the inverse status line (` model · mode · cwd`, `in · out` tokens). **f2** `@alp` opens the completion menu (`.gitignore`d `build/` left out), Tab completes, the model receives a `<file path="src/alpha.lisp">` block. **f3** a markdown answer held mid-stream (spinner, heading, list so far), then finished: heading without `#`, no `**` or backticks, an indented code block, a boxed table, a quote. **f4** an `edit` asks: the Permission dialog with the edit's diff preview and the four answers; "Always allow" (↓ Enter) runs it, the second edit of the same file no longer asks, the transcript shows both diffs, and `.cl-stack-code/settings.local.json` holds `{"permissions":{"allow":["edit(src/greet.lisp)"]}}`; **f4b** a new program on the same project lists that rule under `/permissions` and edits without a dialog. **f5** Reject (3) with typed feedback: the file is unchanged and the model's next request carries the denied tool result with the feedback. **f6** Esc while a generate waits: `interrupted`, the late answer is dropped, the conversation goes on. **f7** a message sent while a turn runs shows as `queued: two` above the spinner and becomes the next turn when the first ends (history kept). **f8** `/help` (nothing goes to the model). **f9** `run-cli` without `-p` on string streams: exit 2 naming the terminal and `-p`. **f10** one turn on the LM Studio model in the same program (skipped without a model; a slow model is interrupted with Esc after 420 s).
- **image** — lisp-mcp 0.6.0's `lisp-mcp/agent` (H4a): lisp-mcp's tools as an ai-agent-protocol tool source, called in this image with no MCP hop.
  - **Demo 1, `form-resources`** — 29 forms (pure, reads, defines, mutates, package, io, read-eval, calls, `lisp:*`) scanned in package `shop` with `observe-safe-resources-p` for each; a definition whose body mutates and prints; `#+(or)`; blank code; an `:observe-allow` glob.
  - **Demo 2, a spawned Swank image through `call-lisp-tool`** — `repl-spawn`, `repl-eval`, `repl-compile` of a located form, a seeded `restart-case` bug returned as the debugger state, the restarts as `restart:return-default` / `restart:abort` / `*` resources, a rule gate (abort denied with feedback, return-default allowed) and the allowed restart giving `=> 42`; a background job (`timeout` 1, then `job-wait`), a bounded result stored as `oN` and read back with `output-read`; three errors as `tool-input-error` with advice; `tool-unavailable` after `close-lisp-tools`.
  - **Demo 3, observe mode** — an observe source attached (`repl-connect`) to a second Swank server in a spawned image: its catalog and `OBSERVE MODE` instruction line, pure and `lisp:reads` evals run, `defparameter`, `print` and `asdf:load-system` refused as `observe-mode-refused` (a `tool-permission-denied`) with only the offending resources, `repl-spawn` refused, the full source seeing `(boundp '*observed*)` → `NIL`, and the image still running after the observer closes.
  - **Demo 4, an agent run (scripted mock)** — rules allow `image:spawn`, `lisp:pure`, `lisp:reads *` and deny `lisp:io` with feedback: the pure evals run, `(print …)` is refused with the feedback, `(setf *answer* 42)` (`lisp:mutates cl-user:*answer*`, undecided) pauses the run for approval. Then a catch-all allow on an observe source: the refusal is a tool result and the run ends `:stop`.
  - **Demo 5, find and fix a seeded bug** — system `shop` (`line-total` ignores `:qty`) loaded into a spawned image; the agent's source attaches to it and gets `repl-eval`, `source-*`, `edit-replace`, `repl-compile` under path / scanner rules (asks are denied with feedback). LM Studio first (this run: `qwen3.5-2b` evaluated the call (8), read both functions, fixed `line-total` with `edit-replace`, saw the image still answer 8, recompiled the file with `repl-compile` and checked `(mapcar #'line-total …)` → `(6 5)`; three ill-formed evals were asked and refused). When the real model does not fix it, or no LM Studio answers (CI), the same prompt and tools run on a scripted mock: read, `edit-replace` with `compile: true`, re-check. The demo checks the image answers 11 and prints the file.

## Windows

All five projects run on windows-latest in CI. The POSIX tools come from Git for Windows on PATH (`sh`, `env`, `printf`, `cat`, `sleep`); temp directories are cleared of read-only attributes (git objects) before deletion. Skipped there, each with a printed reason: fs Demo 5 symlink probes (no `fs-create-symlink` on Windows), fs Demo 6 process-group / tree-kill steps (POSIX groups and signals), agent Demo 4b (the pty child; Unix-only by design). Agent Demo 7 runs the shell tools with Git for Windows' `sh` instead of `cmd.exe` (executor `:process`). The image project loads its demo system through `uiop:parse-native-namestring` (a native Windows path is not a Lisp namestring) and retries deleting its scratch directory (lisp-mcp#18).
