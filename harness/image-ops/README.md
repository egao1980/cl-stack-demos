# image-ops demo: the resize backend hook and stb's native resize

`harness-demos-image-ops` is a tour of **image-protocol 0.3.0**'s `backend-resize` hook and **image-backend-stb 0.3.0**'s native resize on stb_image_resize2, both from GHCR. The hook lets a backend with a native resampler do `resize-image`'s work (and so `thumbnail`'s and `fit-image`'s), but only when the caller names it. The pure-Lisp resampler stays the default and the reference: it gives Pillow 11.3's samples exactly, and a native backend only comes close to them. The protocol's rules R1–R8 are in image-protocol's `src/ops.lisp` ("Backend fast path"). The stb backend's rules S1–S8 are in image-backend-stb's `src/resize.lisp`.

The 0.2.0 editing operations (crop, rotate, flip, five resize filters, thumbnail, `fit-image`, composite) are not toured again here: [`../documents/`](../documents/) section 5 shows them, with all 16 results pixel-equal to Pillow 11.3.0. That demo still gets exact pixels with image-protocol 0.3.0 and image-backend-stb 0.3.0 (checked locally before this demo was added: 113 checks, 0 mismatched).

Everything is in [`src/demo.lisp`](src/demo.lisp) and [`src/support.lisp`](src/support.lisp). The Pillow side is [`crosscheck/pillow_resize.py`](crosscheck/pillow_resize.py). [`demo-output.txt`](demo-output.txt) is the output of the last run, on macOS arm64 with SBCL 2.6.9, with home paths replaced by `~`. The input images are a test card made in code: a colour gradient on the left half and a black-and-white checkerboard on the right, with an alpha ramp in the top half for the alpha formats. No outside asset is used.

## Run

```bash
cd harness/image-ops
cl-repo run -- sbcl --non-interactive --no-userinit --eval '(require "asdf")' \
  --eval '(asdf:load-system "harness-demos-image-ops")' \
  --eval '(harness-demos-image-ops:run-demos)' > demo-output.txt 2>&1
```

It needs SBCL and `cl-repo`. stb comes with image-backend-stb's native overlay (linux amd64 and arm64, darwin arm64, windows amd64). The Pillow column of section 7 also needs [uv](https://docs.astral.sh/uv/) on `PATH`; on its first run uv downloads `pillow==11.3.0` from PyPI. Without uv the column shows `—`, the Pillow checks are skipped and the summary says so. A run takes about five seconds with a warm uv cache. The demo checks each result that has a known answer (123 checks). Timings are printed and not checked. `run-demos` returns `NIL` if a check fails or a section stops on an error, and the harness-demos workflow then exits 1.

## What each section shows

1. **The 0.2.0 operations, and the test card.** A pointer to `harness/documents`, then the 1024 × 768 test card with hand-worked pixel samples, and one 0.2.0 operation: `thumbnail` into 256 × 256 (256 × 192, `:lanczos3`, reducing gap 2), on the pure-Lisp resampler because no backend is named.
2. **What reaches `backend-resize` (R3, R4).** A recording backend that declines shows each call's arguments: the caller's image itself (`eq`), the size, the filter (`:lanczos3` by default), the reducing gap as given (`2` stays `2`, `1.7` stays a single float), none for an image with alpha or for `:nearest`, and `:linear` as `t` or `nil`. `thumbnail` and `fit-image` pass the designator on with their own gap of 2. A backend listed twice is called twice. A resize to the same size, a `thumbnail` that fits and a `fit-image` at scale 1 return the input and call nothing. A backend that answers gives the result its pixels (every sample 128 from a marker backend). The result is a fresh copy of the input with the input's orientation and gamma, not the answer object, and it shares the answer's pixel vector.
3. **Declining backends (R5).** A backend with no `backend-resize` method of its own, followed by the recorder, both decline. All 20 combinations of the 5 filters and 4 formats come out byte-identical to `:backend nil`.
4. **Bad answers and errors (R5, R7).** Five bad answers, each an `image-corrupt` with the backend and a cause that names the broken rule: a vector instead of an image, the wrong size, the wrong format, depth 16, and the input's own pixel vector (answered as 72 × 96 for a 96 × 72 input, so the length matches). The `try-next-backend` restart, taken from `handler-bind`, moves on to stb in `(list gray stb)` or to pure Lisp when no backend is left. A backend's own `image-native-unavailable` (what stb signals when `stbir_resize` fails, S7) reaches the caller unchanged and is recovered the same way.
5. **`*resize-backends*` against `:backend` (R1, R2, R8).** Loading image-backend-stb registers an stb backend for decoding, and that does not change `resize-image`'s samples. Binding `*resize-backends*` opts in for `resize-image`, `thumbnail` and `fit-image`. An explicit `:backend` (including `nil`) wins over the binding, and nothing changes the binding or the registry. Bad designators give `image-invalid-argument` with argument `backend` and the designator itself as the value: a keyword, a class name, a list holding 42, a dotted list, a bad binding. They are reported even when nothing would be resized, and only after the 0.2.0 checks (a width of 0 is reported first).
6. **stb: which filters it serves (S1, S2).** A counting stb backend on a 320 × 240 → 80 × 60 resize answers `:bilinear` and `:bicubic` (close to pure Lisp: max 1 and 3). It declines `:nearest`, `:box`, `:lanczos3` and `:linear t`, whose results are byte-identical to pure Lisp. `:bicubic` is served in all four formats, with the input's format, depth 8, and the input left unchanged.
7. **Closeness: pure Lisp, stb and Pillow 11.3.0 (S8).** Eight cases (four formats, reductions and enlargements, a non-integer ratio, `:reducing-gap 2`), each resized by pure Lisp, by stb and by Pillow through `uv run --with pillow==11.3.0 python -I`. Each case shows max and mean sample differences for each pair, with the colour of alpha formats premultiplied, as S8 measures it. Lisp – Pillow is 0 in every row. stb is at most 10.74 apart (mean at most 0.78), inside S8's bounds of max 43 and mean 3.2.
8. **Timing: pure Lisp against stb.** The median of 11 runs after a warm-up, for 1024 × 768 → 256 × 192 (`:bicubic`, `:bilinear`), 2048² → 512² (RGB, with and without the gap, gray, RGBA), 4096² → 256² and a 4× enlargement. On an M-series Mac, stb is 6.5–17× faster: 0.7 ms against 9.0 ms for 1024 × 768 → 256 × 192 bicubic, and 3.6 ms against 46.6 ms for 2048² → 512². Timings vary by machine.

## Issues

- Open, [image-protocol#8](https://github.com/egao1980/image-protocol/issues/8): the `image-corrupt` for a bad answer reads "Could not decode nil with #<…>: BACKEND-RESIZE answer: …", because the condition keeps the decode-error report and no `:format` is given. Section 4 shows the message. The type, backend and cause are right.
- Filed by this demo, [image-protocol#9](https://github.com/egao1980/image-protocol/issues/9): `:reducing-gap` does not make the pure-Lisp resampler faster. 2048² → 512² bicubic takes 62 ms with gap 2 and 47 ms without (section 8), and `thumbnail` and `fit-image` default to gap 2. The samples are right; the box pre-reduce looks unoptimised.
