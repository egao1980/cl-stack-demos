== 1. The default clock: sub-second, never early (#1)
==============================================================================
  The default clock is MONOTONIC-SECONDS (0.1.0 used GET-UNIVERSAL-TIME, whole
  seconds). It steps by +monotonic-tick+ = 1/1000000000 s here.

  issue #1's repro: :ttl 1 put just after a whole second
    read at once        -> "alice"
    read 1.1 s later    -> NIL   (0.1.0 still returned "alice")
  :ttl 0.3 (sub-second)
    read at once        -> "t-1"
    read 0.35 s later   -> NIL
  :ttl 1/200 (5 ms), 200 puts: gone before 5 ms had elapsed in 0 of them
  :ttl 1/50 (20 ms), 20 puts polled without sleeping: lifetime 20.000 ms .. 20.002 ms

== 2. An injected clock is exact
==============================================================================
  :clock is any function returning seconds as a real. Its readings are taken as
  exact: an entry expires once clock >= put time + TTL (cachetools: timer >= expires).

  put "page" :ttl 600 at t=1000
    t=1599  get -> "<html>"
    t=1600  get -> NIL
    t=1600  delete of the expired key -> NIL (Redis DEL answers 0)
  put "f" :ttl 1/2 and "g" :ttl 0.1 at t=1000 (a float TTL is RATIONALIZEd: 0.1 -> 1/10)
    t=1000.09  f -> "half"  g -> "float"
    t=1000.10  f -> "half"  g -> NIL
    t=1000.49  f -> "half"  g -> NIL
    t=1000.50  f -> NIL  g -> NIL

== 3. TTL values: fractions, 0, negative, infinities, NaN
==============================================================================
  Each value put at t=0 and read at t=0 and at t=10^9 (cachetools semantics for
  the infinities):
    :ttl             t=0      t=10^9
    nil (no TTL)     kept     kept
    1/3              kept     gone
    0                gone     gone
    -5               gone     gone
    +inf (double)    kept     kept
    +inf (single)    kept     kept
    -inf             gone     gone
  :ttl NaN -> cache-error: cache error ("k"): TTL is not a number: #<DOUBLE-FLOAT quiet NaN>

== 5. cache-incr keeps the TTL: a rate-limit window (#2)
==============================================================================
  A rate limit of 3 requests per 60 s window, on an injected clock: the first
  request creates the counter with cas nil -> 1 :ttl 60, later ones cache-incr it.
  cache-incr keeps the entry's TTL, as Redis INCR does (0.1.0 dropped it, so the
  window never ended).

    t=1000  hits 1 -> allowed
    t=1010  hits 2 -> allowed
    t=1030  hits 3 -> allowed
    t=1059  hits 4 -> 429 Too Many Requests
    t=1060  hits 1 -> allowed
    t=1061  hits 2 -> allowed
