== 3. Pixel formats: :rgba, :rgb, :gray, :gray-alpha
==============================================================================
:format picks the pixel layout. pdfium renders BGRA; render-page copies it to
R G B A and converts with image-protocol's CONVERT-IMAGE. Page 0 at 150 dpi:

  format       bytes/px      bytes  red             green           blue            gray bar        white
  :RGBA               4  1,042,500  255 0 0 255     0 255 0 255     0 0 255 255     128 128 128 255 255 255 255 255
  :RGB                3    781,875  255 0 0         0 255 0         0 0 255         128 128 128     255 255 255
  :GRAY               1    260,625  76              150             29              128             255
  :GRAY-ALPHA         2    521,250  76 255          150 255         29 255          128 255         255 255

:gray is BT.601 luma of the :rgba pixel, 0.299 R + 0.587 G + 0.114 B rounded half
up: red 76, green 150, blue 29, checked at every probe. Each format equals
(convert-image (render-page ... :format :rgba) format) byte for byte. The PDF's
0.5 g bar is 128 in every channel.

== 4. :max-pixels and :limits refuse before any bitmap exists
==============================================================================
Page 1 (A4) at 300 dpi is 2480 x 3508 = 8,699,840 pixels. Both limits are checked
after the page size is known and before pdfium allocates a bitmap.

(render-page pdf 1 :dpi 300 :max-pixels 4000000), refused after 0.2 ms
  → IMAGE-PROTOCOL:IMAGE-LIMIT-EXCEEDED: Image pixels 8,699,840 exceeds the limit 4,000,000
    limit :PIXELS, allowed 4,000,000, actual 8,699,840, format :PDF

RENDER-PAGE offers no restart for a refused size (its file header says so). A
caller can set one up. RENDER-SMALLER, around the call, scales the dpi by
sqrt(allowed / actual), rounded down; the handler reads both from the condition:
  handler: Image pixels 8,699,840 exceeds the limit 4,000,000
  restarts set up between the handler and the signal: (HARNESS-DEMOS-PDF-RENDER::RENDER-SMALLER)
  RENDER-SMALLER: again at 203 dpi
  rendered at 203 dpi: 1678 x 2374 = 3,983,572 pixels (allowed 4,000,000)

:limits takes an image-protocol IMAGE-LIMITS (default *IMAGE-LIMITS*, which allows
16384 a side and 2^28 pixels). It counts the BGRA bitmap pdfium renders into, 4 bytes
a pixel, whatever :format is asked for:
(render-page pdf 1 :dpi 300 :limits (make-image-limits :max-width 2000))
  → IMAGE-PROTOCOL:IMAGE-LIMIT-EXCEEDED: Image width 2,480 exceeds the limit 2,000
    limit :WIDTH, allowed 2,000, actual 2,480, format :PDF
(render-page pdf 1 :dpi 300 :format :gray :limits (make-image-limits :max-bytes 16 MiB))
  → IMAGE-PROTOCOL:IMAGE-LIMIT-EXCEEDED: Image bytes 34,799,360 exceeds the limit 16,777,216
    limit :BYTES, allowed 16,777,216, actual 34,799,360, format :PDF
    The :gray result would be 8,699,840 bytes; the bitmap behind it is 34,799,360.
